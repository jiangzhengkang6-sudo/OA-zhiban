# 运行告警运维说明

日期：2026-10-23。功能编号 F-164。管理员入口：`/organization/alerts`；接口：`GET /api/organization/operational-alerts`。要求当前有效管理员身份与组织读取权限，AI 关闭仍可使用。

## 检查范围

独立巡检进程不依赖后端进程或数据库正常启动。每轮并行检查后端存活、数据库连接、通知积压、备份回执、主文字模型、备用文字模型、嵌入模型、严重运行错误及日志文件关键字，共九项。模型主动探测需单独启用，会调用真实服务并产生用量；关闭时显示“待核对”，不表示模型故障。

通知积压包括超时未投递通知、失败或结果不明的通知，以及超时待分派或失败的业务事件；只统计配置租户。严重运行错误采集 `oa-agent`、`app.*` 日志的 ERROR 及以上事件，只保存发生时间，不保存日志正文、异常内容或密钥。独立的“日志关键字”检查读取管理员明确配置的文件，不依赖应用内日志钩子。最近五分钟无新错误或新关键字命中且检查通过后，对应事件恢复正常。

故障持续期间沿用同一事件，只有明确检查通过才关闭；“待核对”不会自动解除故障。保留全部未恢复事件及最近 100 条恢复记录。状态损坏会提示核对，不自动清空去重历史。巡检记录超过三分钟未更新会显示“巡检已中断”；进程、宿主机或网络整体不可用还需外部监测，不能靠同机进程保证通知。

## 本地启动

从 `backend` 目录运行，配置读取 `backend/.env`：

```powershell
# 本地验收进程覆盖，不修改配置文件或发送外部告警。
$env:OPS_ALERT_DELIVERY_ENABLED='false'
$env:OPS_MODEL_PROBES_ENABLED='false'
.venv/Scripts/python.exe scripts/monitor_operations.py --once
.venv/Scripts/python.exe scripts/monitor_operations.py
```

单次巡检退出码：0 无故障，1 存在故障，2 巡检未完成。持续模式需要独立进程常驻；仅打开后端不会自动启动巡检。多进程同时执行受本地文件锁保护。同一状态目录只用于一个租户，后端与巡检必须使用相同的绝对目录、租户与配置。仅允许运行账号访问，勿放入静态文件服务、知识库或共享下载目录；Windows 需配置目录 ACL，文件创建模式不能代替 ACL。

Docker 部署配置读取根目录 `.env`，已提供可选 `monitoring` 配置组，与后端共享持久卷。完成正式环境配置后启动：

```text
docker compose --profile monitoring up -d --build monitor
```

本批仅校验 Compose 配置，没有部署服务器或开启生产告警。

## 配置

| 配置项 | 默认值与用途 |
| --- | --- |
| `OPS_STATE_DIR` | `data/operations-monitor`，私有状态与任务回执目录 |
| `OPS_HEALTH_URL` | 本地 `http://127.0.0.1:8015/healthz`，容器内由 Compose 指向后端 |
| `OPS_POLL_SECONDS` | 60 秒，允许 10–60 秒 |
| `OPS_PROBE_TIMEOUT_SECONDS` | 单项探测 10 秒，最大 15 秒 |
| `OPS_BACKLOG_AGE_SECONDS` | 120 秒，允许 30–180 秒 |
| `OPS_BACKUP_MAX_AGE_HOURS` | 最近成功备份最长间隔 25 小时 |
| `OPS_BACKUP_MAX_RUNTIME_SECONDS` | 备份任务超时 3600 秒 |
| `OPS_MODEL_PROBES_ENABLED` | `false`，显式启用真实模型探测 |
| `OPS_ALERT_DELIVERY_ENABLED` | `false`，显式启用邮件或企业微信告警 |
| `OPS_ALERT_EMAIL_TO` | 专用管理员收件邮箱，不能以业务成员邮箱绑定代替 |
| `OPS_LOG_FILES` | `[]`，最多八个 UTF-8 日志文件的绝对路径，未配置显示“待核对” |
| `OPS_LOG_KEYWORDS` | `["ERROR","CRITICAL","Traceback"]`，1–16 个字面关键字，每个最多 128 字符 |

邮件沿用 SMTP 配置；企业微信沿用现有机器人配置并校验租户与部门。没有可用渠道时页面提示配置缺失。页面不展示收件地址、Webhook、目标指纹或原始服务报错。修改配置后需重启后端和巡检进程。

## 日志文件接入

列表配置使用 JSON 数组。例如 Windows 本地 `.env` 可填写 `OPS_LOG_FILES=["E:/private/logs/oa.stderr.log"]`，以及 `OPS_LOG_KEYWORDS=["ERROR","CRITICAL","严重故障"]`。只接受普通文件的绝对路径，不展开通配符、不递归读取目录；禁止将巡检私有状态目录作为日志来源。关键字按 UTF-8 字节匹配，ASCII 字母忽略大小写，其他文字按字面匹配，不支持正则。文件权限需允许巡检账号读取；日志路径及关键字由管理员维护，不通过浏览器提交。

每个文件每轮最多读取 256 KiB 新内容，另外读取至多 511 字节的前缀与两段至多 64 字节的校验边界，支持中文字符和关键字跨读取、追加边界。首次从文件开头扫描；仍有积压时显示“正在追赶日志扫描进度”，不能据此认为历史记录已检查完毕。命中时间为巡检观察时间，不解析原日志的业务时间，首次扫描旧错误也会产生告警。大文件追赶和文件读取延迟可能影响时效，不能单凭轮询间隔认证五分钟收件。

`logs.json` 保存租户、配置指纹、文件标识、字节位置、边界哈希和最后命中时间，不保存原始路径、关键字或日志内容；该文件与告警状态同受巡检进程锁保护。进程重启继续原进度，旧命中不会每轮重复触发。文件轮换、长度缩短或位置前的边界变化会从头重扫；对 copytruncate 后迅速增长的文件以边界哈希尽力识别，无法保证发现两轮之间已删除的内容或边界相同的覆写，应优先采用重命名轮换并合理保留日志。配置改变会重新扫描，但已有告警历史不会删除。

文件缺失、目录代替文件、权限不足或状态写入失败均显示故障；扫描记录损坏、租户不匹配时保留原记录并显示故障，不自动清空。部分文件不可读时仍检查其他可读文件，优先显示读取故障，并保留已发现的关键字命中时间。连续五分钟无新命中且所有文件扫描完毕后恢复，状态“待核对”不解除已有事件。

Docker 中填写容器内路径，并在部署配置中给 monitor 增加明确的只读日志挂载；当前 Compose 没有自动收集 Docker stdout，也不会读取宿主机全部日志。本机验收仅通过进程环境指向本次后端的两份私有输出日志，未修改实际 `.env`；普通启动未指定文件时仍显示“未配置日志文件”。

## 通知结果核对

每次发送先落盘“结果待核对”，避免进程崩溃后重复发送。明确暂时失败时至少间隔一分钟，最多三次尝试；结果不明不自动重发。恢复通知只发给已受理或结果待核对的故障通知的同一目标，恢复超过五分钟不再补发旧通知。服务已受理不等于邮件已入箱或成员已阅读。

遇到结果待核对，应先检查邮件服务/群消息记录和网络，再由管理员决定后续动作。勿删除状态文件强迫重发。正常轮询、并行探测、限时投递旨在支持 PRD 的“五分钟内告警”目标；外部服务故障、线程内网络调用、宿主机中断等仍影响时效，本批没有认证真实收件五分钟 SLA。

## 备份接入

`run_monitored_backup.py` 包装已有受信备份命令，先写执行中回执，命令成功并生成新的非空文件后计算 SHA256，最后写成功回执；失败或超时写失败回执。不会覆盖既有文件。文件必须在状态目录外，命令参数按数组执行，不经 shell；输出不保存，凭据通过工具的私有配置提供。

在安装 PostgreSQL 客户端的主机上，可使用以下模板，替换主机、端口、数据库和新文件绝对路径，认证使用 `PGPASSFILE` 或服务配置，勿在命令行写密码：

```text
python scripts/run_monitored_backup.py --artifact /private/backups/new-oa.dump -- pg_dump --format=custom --host=<db-host> --port=<db-port> --username=<db-user> --file=/private/backups/new-oa.dump <db-name>
```

本机尚未安装 `pg_dump` 命令，模板未作为本机备份执行。已有 Docker 导出备份仍保留，但不会伪造为本模块的成功回执。每轮巡检核对回执和时效，不持续重算原文件哈希；备份回执也不等于恢复成功。需另行配置备份计划、保留策略、异地副本与定期恢复演练。当前没有新建持续备份计划。

## 验收边界

本地验收关闭真实发送与模型主动探测，使用隔离库验证权限、租户、队列状态、故障恢复、去重、重试和备份命令回执；实际业务库仅用于只读页面验收及限时登录会话。本轮不把测试替身的投递成功当成真实邮箱或企业微信群收到消息。正式环境还需完成真实宕机到达告警的计时、进程托管、主机外监测、持续备份、恢复和部门试用。
