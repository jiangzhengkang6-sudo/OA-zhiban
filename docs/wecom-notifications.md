# 企业微信群通知接入

更新日期：2026-10-26。接入正式通知队列，只使用群机器人，不替代站内信或邮件。

## 群提醒限制

采用服务端白名单，不允许客户端或模型自行指定通知类别。只有本人授权、属于配置部门、当前仍有业务处理权限且在策略生效后产生的事件才可外发。

| 业务 | 可以提醒 | 不进入群提醒 |
| --- | --- | --- |
| 审批 | 待审批、转交后的待办、催办、升级、流程异常 | 申请人的请假或报销结果、抄送、已失效待办 |
| 工单 | 初次分派、转派给新处理人、反馈未解决后的重新处理 | 普通进度、完成、申请人结果通知 |
| 会议 | 正式发布邀请、时间/地点/入会方式变更、取消 | 议题或标题修改、开会/结束、回复、纪要 |
| 其他 | 无 | 邮件、公告、普通任务、任意通知和模型生成文案 |

群里只出现固定类别提示和 OA 链接，不包含姓名、业务正文、金额、理由、单号或附件。多人收到同一个事件只合并发送一次；连续产生的不同事件合成一个批次。相同群发送至少间隔 60 秒，同一业务的催办至少间隔两小时。被冷却规则抑制的催办不积压补发。发送前再次核对本人授权、部门、路由和业务权限。

历史待发送群消息取消并保留原因，不删除已有回执；未入箱的旧事件同样不补发。SMTP 历史队列不受此隔离操作影响。

## 本地配置

在 **`backend/.env`** 填写，不要把 Webhook 放进 `.env.example`、前端或截图。完整地址中的 `key` 等同于机器人密钥。

```dotenv
WECOM_ENABLED=false
WECOM_WEBHOOK_URL=
WECOM_TENANT_ID=local
WECOM_DEPARTMENT_ID=73776b8e-4d68-42c4-83a4-87627fe3efc0
WECOM_TIMEOUT_SECONDS=10
WECOM_POLICY_ACTIVATED_AT=2026-10-26T20:00:00+08:00
WECOM_GROUP_INTERVAL_SECONDS=60
WECOM_NUDGE_INTERVAL_SECONDS=7200
NOTIFICATION_WECOM_WORKER_ENABLED=false
NOTIFICATION_SMTP_WORKER_ENABLED=false
BUSINESS_SCHEDULER_ENABLED=false
```

示例部门 ID 不应直接用于其他环境，必须核对实际部门 ID。本机当前只配置运营部群；一个配置仅绑定一个租户和一个部门，不向其他部门广播。

1. 将机器人完整 Webhook 填入 `WECOM_WEBHOOK_URL`，只接受企业微信官方 HTTPS 群机器人发送地址。
2. 确认群成员和目标部门匹配。首次启用时以实际时间填写带时区的 `WECOM_POLICY_ACTIVATED_AT`，不要照抄示例或在重启时自动刷新；未配置则禁止外发。
3. 登录消息中心，在“授权核对”开启“授权企业微信群提醒”并保存。邮件开关独立，企微无需额外邮箱；默认不替用户授权，管理员只能撤销他人授权，不能代替本人开启。
4. 先保持自动发送关闭，停止旧后端，升级迁移至 `0037`。可运行 `python scripts/verify_restricted_wecom.py` 只读检查配置，运行 `--isolate-history` 隔离当前租户生效前的待发群消息。
5. 获得单条真实测试授权后，运行 `python scripts/verify_restricted_wecom.py --send`。该脚本只投递自身创建的会议邀请，不清空其他队列、不发送 SMTP；固定 `--run-id` 防止中断重跑时创建第二场测试会议，测试后取消会议，并取消自身测试会议尚未发送的 SMTP 和企微提醒。其他历史 SMTP 不动。结果不明时禁止改 run-id 重试。
6. 核对后将 `NOTIFICATION_WECOM_WORKER_ENABLED` 改为 `true` 并重启后端。通知扫描独立运行，业务催办升级调度与后台 SMTP 可继续保持 `false`。已发布业务操作照常入箱，手动公共邮箱 SMTP/IMAP 不由这两个后台开关控制。

## 隐私与结果

- 群内所有成员均可看到提醒，机器人不是个人私信服务。只发送通用提醒和消息中心链接，不发送审批正文、姓名、邮箱、单号或附件。
- `NOTIFICATION_APP_URL` 应为收件人可访问的 OA 地址。本机 `127.0.0.1` 链接只能在开发电脑打开，手机和其他员工电脑无法使用；对外使用前应配置实际 HTTPS 地址。
- 企业微信服务返回成功只记为“服务已接收”，不保证群成员已经阅读。
- 暂时失败最多自动重试 3 次；发送中超时、断连或响应无法确认时记为“结果不明”，禁止自动重发。管理员核对群消息后可备注重试，并接受可能重复的风险；重试仍受白名单、权限、群间隔及催办冷却限制。
- 机器人使用数据库共享限流，同一地址在多个进程中共用额度。限流只推迟投递，不增加尝试次数。Webhook 不落业务表、审计详情或请求日志，只保存其单向指纹。
- 撤销授权、业务权限失效、收件人调离原部门或群地址变更都会阻止旧消息发送。更换 Webhook 后，旧地址的排队消息不会自动迁移到新群。
- 当前未配置钉钉，也未实现企微应用消息、组织同步或机器人入站回调。
