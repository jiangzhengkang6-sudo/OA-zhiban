# 企业微信群通知接入

日期：2026-10-22。接入项目已有正式通知队列，不替代站内信或邮件。

## 本地配置

在 **`backend/.env`** 填写，不要把 Webhook 放进 `.env.example`、前端或截图。完整地址中的 `key` 等同于机器人密钥。

```dotenv
WECOM_ENABLED=false
WECOM_WEBHOOK_URL=
WECOM_TENANT_ID=local
WECOM_DEPARTMENT_ID=73776b8e-4d68-42c4-83a4-87627fe3efc0
WECOM_TIMEOUT_SECONDS=10
```

此部门 ID 是当前本地“项目部门”的内部 ID；其他环境必须换成自己的部门 ID。一个配置仅绑定一个租户和一个部门，不向其他部门广播。

1. 将机器人完整 Webhook 填入 `WECOM_WEBHOOK_URL`，只接受企业微信官方 HTTPS 群机器人发送地址。
2. 确认群成员和目标部门匹配后，将 `WECOM_ENABLED` 改为 `true` 并重启后端。
3. 登录消息中心，在“授权核对”开启“授权企业微信群提醒”并保存。邮件开关独立，企微无需额外邮箱；默认不替用户授权，管理员只能撤销他人授权，不能代替本人开启。
4. 之后新产生且收件人仍有权限处理的业务通知才会进入企微队列，不补发启用前的历史通知。保存配置本身不会发送测试消息。

## 隐私与结果

- 群内所有成员均可看到提醒，机器人不是个人私信服务。只发送通用提醒和消息中心链接，不发送审批正文、姓名、邮箱、单号或附件。
- `NOTIFICATION_APP_URL` 应为收件人可访问的 OA 地址。本机 `127.0.0.1` 链接只能在开发电脑打开，手机和其他员工电脑无法使用；对外使用前应配置实际 HTTPS 地址。
- 企业微信服务返回成功只记为“服务已接收”，不保证群成员已经阅读。
- 暂时失败最多自动重试 3 次；发送中超时、断连或响应无法确认时记为“结果不明”，禁止自动重发。管理员核对群消息后可手动重试，并接受可能重复的风险。
- 机器人使用数据库共享限流，同一地址在多个进程中共用额度。限流只推迟投递，不增加尝试次数。Webhook 不落业务表、审计详情或请求日志，只保存其单向指纹。
- 撤销授权、业务权限失效、收件人调离原部门或群地址变更都会阻止旧消息发送。更换 Webhook 后，旧地址的排队消息不会自动迁移到新群。
- 当前未配置钉钉，也未实现企微应用消息、组织同步或机器人入站回调。

## 验证范围

自动化使用假 HTTPS 传输和独立测试数据库，覆盖服务响应、超时分类、授权与部门范围、发送前权限核验、结果不明人工重试、共享限流和旧 SMTP 兼容。开发测试不访问真实机器人，也不发送真实邮件。真实群收件需要另行做一次明确的联通测试。
