## 扫描服务准备

当前没有运行真实 ClamAV。Docker 总内存约 3.8 GiB，已有服务约占 1.2 GiB；
独立扫描编排设置 3 GiB 内存上限。该上限只是部署限制，不代表已测得的实际需求。
本次没有挤占现有服务资源启动扫描引擎，也没有验证镜像拉取、签名更新或真实检出。
部署前需要确定可用镜像版本/摘要、资源余量与病毒库更新网络。

准备私有 `.env.scanner`，参考根目录 `.env.scanner.example`，
填写已批准的 ClamAV 镜像；生产使用经验证的固定摘要。
从项目根目录启动独立扫描项目的命令为：

```powershell
docker compose -p oa-attachment-scanner --env-file .env.scanner -f docker-compose.scanner.yml up -d scanner
docker compose -p oa-attachment-scanner --env-file .env.scanner -f docker-compose.scanner.yml ps
```

此命令只管理新扫描项目，不创建或重启 OA 数据库、后端和前端。
扫描端口仅发布至 `127.0.0.1:3310`，签名存放于独立 Docker 卷。
健康检查仅证明服务响应，仍需完成下述干净样例和标准测试签名验证。

本机后端的私有配置：

```dotenv
CLAMD_HOST=127.0.0.1
CLAMD_PORT=3310
ATTACHMENT_SCAN_TIMEOUT_SECONDS=10
```

容器后端不能用 `127.0.0.1` 连接另一个容器。将基础编排与扫描编排合并时，
同一 Compose 项目中的后端使用 `CLAMD_HOST=scanner`、`CLAMD_PORT=3310`，
由默认私有网络连接；不要把独立项目的容器名称当作可跨网络访问的服务地址。
单独扫描编排只支持本机后端接入，容器整合需要使用相同项目和网络后再验证。

## 验证入口

从 `backend/` 执行：

```powershell
.\.venv\Scripts\python.exe scripts/verify_attachment_scanner.py
.\.venv\Scripts\python.exe scripts/verify_attachment_scanner.py --include-test-signature
```

默认仅检查干净流。第二条命令额外向扫描服务发送标准、无害的 EICAR 测试字节，
不写入磁盘；必须返回检出才通过。只会返回“正常”的假扫描服务不能通过此检查。
报告不包含附件正文、路径、连接凭据或原始服务异常。未配置或失败时退出码为 1。
所有报告保留 `production_acceptance=false`，不把单一测试等同于生产安全保证。

原 `verify_live_services.py` 在配置扫描地址后也会检查干净流，
但始终把病毒检出能力保留为待验证，不会主动发送测试签名。

现有未扫描附件不会自动变为通过。引擎就绪后，在原申请中执行重新扫描；
未扫描、扫描失败、检出风险和文件完整性失败均继续阻止提交。
