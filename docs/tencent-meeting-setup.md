## 本地配置

私有配置位于 `backend/.env`，示例位于 `backend/.env.example`：

```dotenv
TRTC_SDK_APP_ID=0
TRTC_SDK_SECRET_KEY=
TRTC_USER_SIG_EXPIRE_SECONDS=3600
TRTC_ADMIN_USER_ID=administrator
```

用同一 RTC 应用的 SDKAppID 和 SDKSecretKey 替换占位值；当前配置已确认属于应用 `1600168994`。`TRTC_ADMIN_USER_ID` 必须填写控制台配置为 App 管理员的账号 UserID，默认值 `administrator` 已通过只读查询验证。

SDKSecretKey 仅供后端签发短期 UserSig，不填写到前端、示例文件、聊天或版本库中。
配置加载不会自动开通腾讯服务，也不会创建可用的视频房间。

## 使用方式

创建会议时勾选“启用腾讯视频会议”。主持人开始会议后，受邀成员从详情点击加入；结束/取消会关闭房间。安排人数最多 100，但体验套餐的房间人数限制以腾讯控制台为准。

普通受邀成员只需会议读取权限即可获取本人入会凭证，不因此获得开始或结束会议的权限。未受邀、跨租户、会议未开始或已关闭时均不能入会。成员退出视频不会结束业务会议；视频房间被解散后立即禁用再次加入，并继续同步 OA 会议状态。

### 复跑

仅在上述隔离实例启动、数据库迁移就绪、两个专用测试账号仍存在时，从项目根目录执行：

```powershell
$env:OA_VIDEO_LIVE_ACCEPTANCE='1'
node frontend/e2e/verify-meeting-video-live.mjs
```

脚本固定使用上述隔离数据库、后端及前端端口，测试账号在脚本中明确指定；不得改指向主业务库。启动隔离前端时设置 `OA_BACKEND_PORT=8016`，并使用 `--port 5183 --strictPort`。启动隔离后端前，必须将数据库、同步数据库、Checkpointer 三项连接统一指向隔离库，停用 SMTP、企业微信和定时副作用，再运行 `backend/scripts/serve_business_acceptance.py --port 8016`。缺失账号或环境时应先准备隔离环境，不要借用真实员工会话。

脚本需要 Microsoft Edge 和项目本地依赖，显式授权后才运行真实服务。无论成功失败，都会尝试关闭本轮会议、销毁房间并撤销测试会话。私有脱敏回执和截图保存在 `output/business-acceptance-private/meeting-video/`，该目录不进入版本库；应同时检查 `passed`、`room_cleanup_confirmed` 和 `sessions_revoked`。
