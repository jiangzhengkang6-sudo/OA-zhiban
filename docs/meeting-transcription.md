# 视频会议转写与纪要草稿（第一版）

## 已实现的流程

发起人或主持人在已经开始的视频会议中勾选记录授权，再确认开启转写。腾讯 TRTC 2.0 ASR 接收房间中实际发布的音频，回传完整语句；系统按参会人、时间保存并去重。页面每 5 秒更新一次状态。

结束会议会请求停止转写；收到退出结果后至少等待 90 秒，且最近 15 秒没有回调，才整理已收到的文本。现有文字模型生成可审阅的纪要草稿，不自动确认发布，不自动发送纪要或创建业务任务。发起人仍需审阅来源、修正内容并确认。

原始临时转写仅向发起人、主持人、记录人开放；其他参会人可见记录状态和告知信息。所有接口遵守当前租户、参会范围和会议权限。关联纪要沿用现有纪要权限，具备部门或全局纪要权限的账号也可能查阅其来源证据，不能把临时列表权限等同于归档纪要权限。

第一版只处理语音文本，不保存音视频文件，不识别屏幕共享、PPT、图片或聊天消息，不做翻译和语音合成。仅记录开启后收到的音频，静音、断网、未发布音频及丢失回调可能导致缺失；页面始终提示记录范围，不宣称完整记录会议全程。

## 配置腾讯云

1. 在现有视频应用对应的腾讯云项目中开通 TRTC 2.0 语音转文字，确认该应用的服务权限及 ASR 计费。视频通话免费分钟不代表已具备 ASR 免费额度。
2. 准备腾讯云 API 的 SecretId、SecretKey，供后端调用 CreateCloudTranscription、DeleteCloudTranscription、DescribeCloudTranscription。它们与生成 UserSig 的 TRTC SDKAppID、SDKSecretKey 是两套配置，不能互换。SecretId/SecretKey 必须具备这三个操作的权限。
3. 在腾讯控制台为同一 SDKAppID 设置转写回调地址和回调签名密钥。地址应为公网可达的 HTTPS，例如 `https://你的服务地址/api/meeting-transcriptions/callback/trtc`。本机 `127.0.0.1` 不能接收腾讯回调；本地试用需要 HTTPS 转发或后续服务器部署。
4. 回调密钥使用 16 至 32 位英文字母和数字，与后端配置保持一致。回调地址、密钥在控制台设置，不放入创建转写任务的参数。
5. 在私有 `backend/.env` 中填写下列配置。Docker Compose 则填写根目录私有 `.env`。不要把密钥写入 `.env.example` 或前端。

```dotenv
MEETING_TRANSCRIPTION_ENABLED=false
MEETING_TRANSCRIPTION_SECRET_ID=
MEETING_TRANSCRIPTION_SECRET_KEY=
MEETING_TRANSCRIPTION_CALLBACK_KEY=
MEETING_TRANSCRIPTION_CALLBACK_URL=
MEETING_TRANSCRIPTION_REGION=ap-guangzhou
MEETING_TRANSCRIPTION_LANGUAGE=bigmodel-zh
MEETING_TRANSCRIPTION_RETENTION_DAYS=30
```

现有 `TRTC_SDK_APP_ID` 和 `TRTC_SDK_SECRET_KEY` 也必须有效。所有配置就绪并明确同意真实 ASR 测试后，将开关改为 `true` 并重启后端。配置不完整时页面显示“会议转写尚未配置”。现有 DeepSeek/豆包文字模型承担纪要整理；嵌入模型不参与音频识别，无需另加 TTS 或视觉模型。

### 本次待填写的配置

本机开发使用 `backend/.env`；根目录 `.env` 用于 Docker Compose，二者不会自动同步。本次已在 `backend/.env` 开头补齐空白项，保留原有配置。先填写该文件即可，已有视频密钥无需重填。今后使用 Docker 时，再按根目录 `.env.example` 准备私有 `.env`。示例文件与本文均不填写真实密钥。

| 配置项 | 填写内容或来源 |
| --- | --- |
| `MEETING_TRANSCRIPTION_SECRET_ID` | 腾讯云访问管理中，为具备上述三个转写 API 权限的用户创建的 SecretId |
| `MEETING_TRANSCRIPTION_SECRET_KEY` | 与上述 SecretId 配对的 SecretKey；仅保存在私有配置中 |
| `MEETING_TRANSCRIPTION_CALLBACK_KEY` | 自行设置的 16 至 32 位英文字母和数字，同时填入腾讯回调配置 |
| `MEETING_TRANSCRIPTION_CALLBACK_URL` | 公网 HTTPS 地址加 `/api/meeting-transcriptions/callback/trtc` |
| `MEETING_TRANSCRIPTION_ENABLED` | 配置阶段保留 `false`；准备真实验收时再开启并重启 |

腾讯 TRTC 控制台进入「应用管理」，选择与视频会议相同的应用，点击「配置管理」，进入「回调配置」。设置回调密钥，在回调地址中填写「AI 转录 2.0 回调」。另需确认该应用已开通 AI 转录服务。官方指引：https://cloud.tencent.com/document/product/647/52428 。腾讯云访问管理中使用具备上述权限的用户获取 API 密钥，不与视频 SDKSecretKey 混用；密钥管理说明：https://cloud.tencent.com/document/product/598/40488 。

没有服务器或域名时，可使用你自行选定的公网 HTTPS 转发服务，将该回调路径转发到本机后端 `8015`；也可等部署服务器后再填写。不能填写 `localhost`、`127.0.0.1`、局域网地址或前端 `5182` 地址。转发地址变更后须同步修改控制台和私有配置。

在项目根目录运行静态检查：

```powershell
& .\backend\.venv\Scripts\python.exe .\backend\scripts\check_meeting_transcription_config.py
```

检查 Docker 配置时可追加 `--env-file .env`。检查只输出字段是否通过及修改提示，不输出密钥，不连接数据库、不请求腾讯服务。退出码 `0` 且 `ready_to_enable=true` 表示本地格式齐全；即使如此，`enabled=false` 时仍未开启。退出码 `1` 表示缺失或格式错误。进程环境变量优先于配置文件，长期运行的后端需要重启才能读取改动。

静态检查不能证明密钥有效、权限齐全、证书有效、回调可达或计费额度可用；真实验收仍按文末流程进行。

接口依据腾讯云官方文档：

- TRTC 2.0 接入：https://cloud.tencent.com/document/product/647/131290
- 创建任务：https://cloud.tencent.com/document/product/647/129058
- 回调协议：https://cloud.tencent.com/document/product/647/131295

## 数据、安全与故障处理

- 回调按原始请求体校验 HMAC-SHA256 签名、SDKAppID、5 分钟时间窗，再绑定房间、机器人、任务和参会人；拒绝跨应用、跨房间及未知人员文本。翻译事件不入库。
- 任务在调用云接口前持久化。创建接口超时后显示“结果待核对”，不自动重建，以免重复任务及重复计费。请到腾讯控制台按房间、机器人核对；收到有效回调可恢复任务 ID，否则需要管理员在云端核对并停止孤立任务。第一版没有手工填写 TaskId 的管理入口。
- 已知任务可重试停止并查询退出状态；结束或取消会议、关闭智能功能或转写开关、达到 8 小时、到保存期限或达到单场 1 万条语句上限时会请求停止。请保留云端凭据直到退出确认；删除凭据导致停止失败时仍需到云端人工核对。
- 自动整理失败进入“需要人工处理”，可在保存期限内重试整理；重试不创建新 ASR 任务。已有人工纪要不会被自动覆盖。模型及权限异常可直接打开纪要人工处理。
- 草稿生成时固定文本范围；后到的句子显示“未纳入当前纪要”，需要人工补充，不悄悄改写草稿。纪要整理最多处理 10 万字符，超过时转人工分段处理；页面最多显示前 2000 条，整理会读取冻结时全部已保存的语句。
- 临时语句默认保留 30 天，可配置 1 至 365 天；过期后不再展示并由后台清理。任务审计仍保留。已写入纪要的来源文本、草稿和版本按现有纪要规则保留，**不会随临时列表到期一起删除**。
- 本功能不自动发送真实邮件或企业微信消息。模拟测试不证明真实语音识别准确率、费用或公网回调可用性；下方单独记录真实服务验证范围。

真实服务配置完成后的验收流程：

1. 用两位参会人的真实设备入会，确认双方麦克风已发布音频；发起人完成告知和授权后开启转写，检查持续的记录提示。
2. 双方分别朗读不同句子和明确待办，检查发言人、时间、文本及普通参会人的查看限制。
3. 停止转写后继续说话，核对文本范围；结束会议，等待退出与剩余回调，再查看自动生成的草稿。
4. 核对摘要、决定、负责人、期限和来源，人工确认发布；验证结束会议后腾讯控制台任务已退出，并核对 ASR 费用。
5. 用真实麦克风、弱网和断线重连检查缺失提示。以上多人设备、弱网及费用验收仍未执行，不能用合成语音或模拟测试替代。
