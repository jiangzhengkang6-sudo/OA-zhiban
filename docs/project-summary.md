# OA 智能体管理系统项目总结

日期：2026-10-14。当前状态：P1-P3 主要功能已完成，本地 Mock 工程验证通过，真实企业接入与生产验收待完成。

## 1. 项目背景与问题分析

传统 OA 中，申请填报、制度咨询、材料整理与任务跟进依赖大量人工操作。信息分散在会议、邮件和工单中，处理过程不透明，重复沟通较多。

本项目在现有 OA 之上增加智能编排层，将自然语言理解、内容起草与业务流程连接起来。智能体提供建议，确定性规则负责校验，重要结果由人工确认。

## 2. 技术架构概述

采用前后端分离架构，业务服务、智能体编排和外部系统适配分层实现。

| 层级 | 技术与职责 |
| --- | --- |
| 前端 | Vue 3、TypeScript、Element Plus，提供角色工作台、审阅和管理界面 |
| 后端 | FastAPI，处理接口、权限、业务状态和事务 |
| 智能编排 | LangGraph 管理流程与人工中断；DeepAgents 处理长合同计划和分块读取 |
| 数据存储 | PostgreSQL、pgvector，保存业务数据、知识向量、版本和流程检查点 |
| 适配与运行 | 模型/OA 适配层、Mock 提供方、Docker 数据库及 Alembic 增量迁移 |

典型链路：用户输入 → 权限与规则检查 → 智能分析 → 人工审阅 → 保存业务结果与审计记录。

## 3. 核心功能介绍

- **请假审批**：申请预检、审批路由、人工审批、状态查询与内部催办。
- **智能客服**：知识检索、来源展示、工单处理与带上下文转人工。
- **会议、文档与邮件**：生成纪要、待办候选和内容草稿，支持编辑、版本比较及人工确认；邮件仅保存回复草稿。
- **业务任务**：从授权来源提取候选，人工指定负责人和期限，支持进度、完成、取消、归档与内部提醒。
- **只读报表**：批准统计计划后查询权限内数据，展示真实指标图表，审阅后发布平台记录。
- **合同辅助审查**：私有文本/TXT/文本 PDF 输入、条款证据定位、风险提示和指定人员复核；长文实际接入 DeepAgents。
- **平台治理**：角色权限、审计追踪、运行限额、场景开关、故障降级与恢复。

## 4. 项目开发中遇到的问题

- **重复请求与恢复一致性**：响应丢失、并发操作和服务重启可能造成重复创建；流程检查点与业务提交也不能天然保持原子性。
- **权限变化与信息隔离**：生成、历史查询和请求重放期间撤权，需要重新校验；公共任务入口还可能泄露私有内容。
- **模型输出可靠性**：报表摘要可能交换数字，合同输入可能包含诱导指令，分析结果需要可验证证据。
- **调度与界面细节**：提醒扫描存在候选饥饿风险；手机图表日期曾重叠，浏览器截图也需等待加载与滚动完成。
- **运行环境兼容性**：Windows 默认事件循环与异步检查点组件不兼容，需要专用启动入口。

## 5. 项目实现方案

按 P1 业务基础、P2 内容辅助、P3 业务智能体分阶段实现，并复用统一身份、工具和审计设施。

通过业务状态机、版本检查、幂等账本和数据库事务控制重复操作，以业务记录作为恢复时的决定依据。各入口刷新权限，私有数据按租户和参与人隔离，公共投影脱敏。

报表使用登记指标与参数化只读查询，数值由数据库快照提供，模型摘要限制为定性描述。合同采用四节点流程和证据校验，DeepAgents 仅允许计划与合同分块读取工具，并设置调用、输出和超时上限。

高影响结果保留人工确认；各场景可独立关闭。Mock 身份、模型及 OA 适配器用于验证流程，报表 SQL、数据库持久化和长合同 DeepAgents 引擎实际运行。

## 7. 项目亮点与创新点

- **智能与业务规则协同**：将模型理解能力与确定性规则、人工确认结合，降低不可控操作风险。
- **从信息到业务结果**：将会议待办转为可跟踪任务，将查询结果转为可审阅报表，将合同风险关联到原文证据。
- **受限长文分析**：在 LangGraph 主流程中接入真实 DeepAgents，保留工具白名单、预算和人工决定边界。
- **可追踪、可恢复、可替换**：业务版本、审计和检查点支撑追溯；适配层为后续替换真实模型与 OA 留出接口。

## 8. 项目收获总结与展望

项目实践表明，智能体工程不仅需要提示词和模型调用，更需要权限、事务、幂等、证据和故障恢复共同保障。自动化测试与真实浏览器检查也能发现接口测试难以覆盖的交互问题。

目前 Mock 版本已具备主要业务演示与本地工程验证能力。下一阶段重点是接入真实企业身份、OA 沙箱和业务数据，验证实际模型效果、成本与延迟，完善法务规则、文件扫描及人工验收，并进一步优化性能和前端包体积。完成这些验证后，再开展生产灰度上线。
