## 三、员工请假流程

### T03 新建并保存请假草稿

1. 切换为 u_emp_001。
2. 点击“我的请假” → “新建请假”。
3. 选择“年假”。
4. 填写开始时间、结束时间和请假原因。
5. 点击“保存草稿”。
6. 返回“我的请假”，确认申请出现在列表中且状态为“草稿”。
7. 刷新浏览器，重新打开该申请。

预期：草稿内容保留，版本号可见，刷新后仍能恢复。

### T04 预检并提交正常请假

1. 打开 T03 的草稿。
2. 点击“预检并提交”。
3. 查看“预检结果”卡片。
4. 确认状态进入“审批中”或等待人工审批，并出现“查看审批进度”。
5. 点击“查看审批进度”，确认能看到业务单号、预检结果、审批节点和当前审批人。

预期：预检结果逐项展示；没有人工决定前，不应直接变成最终批准。

### T05 两级审批

1. 切换为李四，打开“审批待办”。
2. 确认只能看到当前由李四负责的节点。
3. 打开申请，填写审批意见，选择“批准”。
4. 切换为王五，刷新“审批待办”。
5. 确认王五现在可以看到该申请，完成第二级批准。
6. 切换回张三，查看申请状态和审批历史。

预期：一级批准后不会提前完成；二级批准后状态为“已批准”；审批人、意见和时间均可追溯。

### T06 驳回、修改和重新提交

1. 新建或选择一条处于审批中的请假申请。
2. 使用当前审批人执行“驳回”，填写明确原因，例如“请补充说明”。
3. 切换回张三，打开申请详情。
4. 确认显示驳回原因，修改请假原因或时间。
5. 点击“重新预检并提交”。
6. 查看版本历史和字段差异。

预期：驳回原因保留；重新提交产生新版本；旧版本不能被覆盖。

### T07 附件和安全扫描

1. 在请假草稿中先保存，再上传 PDF、PNG 或 JPEG 附件。
2. 确认附件显示“待扫描”或实际扫描状态。
3. 在非 CLEAN 状态下点击下载。
4. 如环境未配置 ClamAV，确认待扫描附件不能作为审批依据，页面提示重新扫描。
5. 不要上传真实敏感资料，使用测试文件即可。

预期：超过 10 MB、非法类型或未通过扫描的文件不能被审批或下载。

## 四、智能助手、FAQ 和工单

### T08 FAQ 知识问答

1. 切换管理员，进入“知识库”。
2. 导入一份短文档，例如：年假需要提前一天提交申请。病假需要医院证明。
3. 切换员工，进入“智能助手”，选择“知识问答”。
4. 新建会话，输入“年假需要提前多久提交？”，点击发送。
5. 检查回答、来源文档、片段位置和置信度。

预期：回答有来源；未命中问题不应编造确定性答案，应转人工核实且不生成工单草稿。请先确认所需知识已发布且当前员工有检索权限。

### T09 工单草稿、编辑和确认

1. 员工进入“智能助手”，选择“工单办理”。
2. 新建会话，输入“我的电脑无法开机，请帮我报修”。
3. 检查工单草稿中的类别、优先级和摘要。
4. 点击“编辑草稿”，修改摘要或优先级。
5. 点击“确认创建工单”。
6. 打开生成的工单号，确认状态、队列、责任人和时间线；未命中分派规则时应显示“未分派”“待领取”，不应编造责任人。
7. 刷新页面，再次打开工单。

预期：确认前不创建正式工单；确认后只有一个工单；刷新后数据仍在。

### T10 转人工

1. 员工在 FAQ 或工单会话中点击“转人工”。
2. 切换客服，进入“客服队列”。
3. 确认队列项包含摘要、可读原因和用户；点击“查看上下文快照”，在处理详情查看脱敏交接内容。

预期：交接上下文不包含 token、密码、API Key 等敏感字段。

### T11 客服受理、转派和完成

1. 客服打开一个待受理队列项。
2. 点击“受理此项”。
3. 输入目标客服账号并点击“转派”，或直接填写处理结果。
4. 点击“完成并回写”。
5. 打开关联工单工作台。

预期：状态从待受理 → 处理中 → 已解决/已关闭；工单时间线和处理结果同步更新。

## 五、管理员治理和运维

### T12 知识来源和版本发布

1. 管理员进入“来源治理”。
2. 选择 Markdown、HTML 或 PDF 测试文件。
3. 点击“预览解析”，确认可以看到解析结果。
4. 点击“创建草稿”，确认出现版本号和解析状态。
5. 点击“发布版本”。
6. 回到知识库或 FAQ，确认发布版本可参与检索。

预期：版本发布是显式操作；同一来源只能有一个当前发布版本；历史版本保留。

### T13 策略版本发布和回滚

1. 管理员进入“策略版本”。
2. 创建一个 faq 或 ticket 的全局策略草稿。
3. 填写合法阈值 JSON，点击“创建策略草稿”。
4. 点击“发布”。
5. 点击“回滚为新版本”。

预期：发布后版本不可覆盖；回滚生成新版本；时间线中保留旧版本。

### T14 审计中心

1. 管理员进入“审计中心”。
2. 按场景、动作、业务单号或 trace_id 查询。
3. 点击“导出当前筛选”。
4. 检查导出记录和下载结果。

预期：可看到会话、预检、人工决定、工单、配置或降级事件；普通员工访问应被拒绝。

### T15 运维观测和 Trace

1. 管理员进入“运维观测”。
2. 点击刷新指标，确认页面能加载。
3. 从接口响应或审计记录中复制一个 trace_id。
4. 在 Trace 输入框查询。
5. 检查节点时间线、工具错误和模型用量未知标记。

预期：空数据时显示 0 或暂无数据，不应出现 404；员工访问应被拒绝。

### T16 降级和恢复

1. 管理员进入“降级控制”。
2. 选择 faq、leave 或 ticket。
3. 新任务选择回退人工，在途任务选择暂停，填写原因并点击“立即降级”。
4. 员工发起对应场景的新请求。
5. 确认新请求按降级策略处理，不调用智能路径。
6. 对已有会话发送消息，确认在途任务按配置暂停或继续。
7. 管理员点击“恢复”。

预期：降级记录保留原因、操作者、生效和恢复时间；恢复后新请求回到正常路径。

## 七、P2 会议文本实测

以下步骤使用员工账号和非敏感样例文本，会议确认只保存平台记录，不创建外部 OA、任务、日历或邮件。每个场景请记录 meeting_id 和 trace_id；不要把真实机密会议原文贴进反馈或截图。

### T19 创建、生成与来源核对

1. 切换为张三 · 员工，打开“会议文本”（`/meetings`）。
2. 输入标题“P2 验收会”，文本“议题：验收会议工作台。决定：保留人工确认。待办：整理反馈。”，点击“创建会议”。
3. 记录地址中的 meeting_id，点击“生成草稿”。
4. 核对纪要、议题、决策、待办与来源 1 的原文；点击来源链接应定位到对应片段。
5. 查看负责人和截止时间：原文未明确时应留空并提示待确认。

预期：草稿带来源引用，显示版本和下一步动作；页面明确提示本阶段无外部写入。空标题或空文本时创建按钮不可用。

### T20 编辑、确认和刷新恢复

1. 在 T19 草稿修改纪要、决策或待办，选择有效来源并保存新版本。
2. 确认版本号增加；有未保存修改时确认按钮不可用。
3. 点击“确认草稿”，在二次确认框点“OK”。
4. 刷新页面，并从“我的任务”重新进入此会议。

预期：状态“已确认”，编辑内容和来源保留，确认动作不会写入外部系统。实际外部写入零调用由自动化测试约束；浏览器无法单独证明真实外部系统状态。

### T21 拒绝与重新生成

1. 新建另一场会议并生成草稿，点击“拒绝”，先尝试空原因，再填写具体原因并提交。
2. 重新打开该会议，核对状态“已拒绝”。
3. 再新建一场会议并生成草稿，点击“重新生成”并确认。

预期：空原因不可提交；拒绝结果刷新后保留；重新生成创建新版本，旧版本由服务端保留并可由审计追溯。不要对已确认/已拒绝的任务重复执行编辑。

### T22 暂停、恢复和失败重试

此场景需要测试环境模拟生成依赖故障；正常页面无法稳定手工制造 PAUSED。拿到暂停 meeting_id 后打开详情，记录错误和 trace_id，点击“从恢复点重试”，刷新并核对版本。不要为制造故障操作开发数据库或 Docker 卷。

预期：重试从 Checkpoint 恢复，已完成版本和审计事件不重复。浏览器的丢响应/刷新重放测试与后端独立测试库的故障注入测试见验收记录。

### T23 权限和审计

1. 员工创建会议后，切换另一账号直接打开该 meeting_id；核对标题和原文不泄露。
2. 管理员打开有访问权限的会议，点击“查看审计轨迹”，核对业务号筛选、创建/生成/编辑/决定事件和 trace_id。
3. 如具备权限管理测试条件，撤销测试账号会议角色后重试详情读取和草稿保存；否则标记“待环境支持”。

预期：每次读取和写入重新鉴权，跨租户与撤权请求被拒绝；普通员工不显示会议审计快捷入口。前端菜单只是提示，授权以服务端为准。

## 八、P2 文档与邮件实测

本次隔离预览服务为 `http://127.0.0.1:5182`，连接 Mock 身份/模型/OA 与 `oa_agent_test`。选择“张三 · 员工”。下列 T24-T29 为待人工执行步骤，自动化结果另见 `docs/p2-document-acceptance.md`、`docs/p2-email-acceptance.md`。请记录 DOC-/MAIL- 业务号与出错时的 trace_id。

### T24 文档创建与模板检查

1. 打开“文档起草”，选择“通知”，录入标题“项目验收通知”、接收对象“项目组”、期限“2026-10-20”、依据“验收计划”、要点“请各组提交验收材料”、分发范围“项目组内部”。
2. 创建文档并生成草稿，核对四类模板可选、模板章节、来源、密级和期限。
3. 另建一条未填写期限的样例，检查待确认提示；空必填项应无法创建。

预期：材料和模板保存为快照，生成草稿为 v1；占位或缺失章节不能直接确认。

### T25 文档修订、比较与终态

1. 修改正文；未保存时确认按钮不可用。尝试离开并取消，正文修改应保留。
2. 保存修订到 v2，选择历史 v1 比较，核对旧正文没有被覆盖。
3. 核对元数据与风险提示后确认内部记录，刷新，并从“我的任务”的文档筛选重新打开。
4. 另建样例测试拒绝原因和重新生成，不对终态样例重复编辑。

预期：确认后正文只读，确认/编辑动作消失，业务号、v2 和已确认状态保持；没有外部发文。

### T26 文档知识权限

需要已有租户归属、已发布、生效且 READY 的测试知识版本；缺少该条件时标记“待环境支持”。创建时开启“引用知识库”，核对来源版本与正文位置。用另一租户/无权部门的账号尝试访问；再撤销原账号的来源访问权限，复验详情、历史及已有命令重放。

预期：无权、未发布、失效或非 READY 的知识不进入草稿；权限撤销后的读取和命令均拒绝且不显示材料内容。不要通过删除正式数据制造此场景。

### T27 邮件录入、分析与修订

1. 打开“邮件工作台”，录入主题“验收材料”、发件人“partner@example.com”、收件人“project@example.com”、正文“请项目组整理验收材料。请于下周反馈结果。”。
2. 打开“涉及外部联系人”，添加附件名称“验收清单.xlsx”并勾选“敏感”；创建审阅记录并分析邮件。
3. 核对分类、优先级、摘要、待办候选和回复；原文未明确的负责人/具体期限应留空待确认。
4. 修改回复并保存 v2；比较 v1 与当前版本的中文业务字段。

预期：来源可对应邮件原文；只记录附件名称与敏感标记，无附件上传、解析或自动任务创建。

### T28 邮件二次确认与刷新

1. 核对联系人、待办、回复和附件信息，并勾选风险提示。
2. 点击确认内部记录，在第一层确认后取消“二次确认”，刷新核对仍未确认。
3. 再确认并通过两层确认框，刷新，再从“我的任务”的邮件筛选回到同一邮件。

预期：缺少核对不能确认；取消二次确认不提交决定；通过后状态已确认、版本与回复保留且不可编辑。已确认表示内部记录完成，不表示邮件发送。

### T29 文档/邮件权限与故障恢复

1. 切换其他账号直接打开上述业务号，应无法读取正文/草稿/历史；管理员只能按权限查看任务摘要。

3. 测试环境模拟模型故障后打开暂停记录，核对脱敏错误与 trace_id，显式重试并查看版本。故障样例由测试环境提供，不操作正式库或 Docker 卷。

预期：撤权拒绝内容返回；重试保存一个新版本，失败重新生成不会覆盖已有版本。版本冲突时保留本地修改供核对。实际权限/事务/丢响应边界也由独立自动化用例覆盖。

## 九、P3 业务任务、报表和合同实测

使用 5182/8012 和 `oa_agent_test`，不要放入真实合同或企业资料。每项记录账号、WTB-/WT-/RPT-/CON- 业务号及失败响应的 trace_id。合同演示复核人采用审批人或管理员角色，不等于企业法务岗位。

### T30 授权来源与任务候选

1. 张三创建一条新会议，输入“议题：P3 验收。待办：整理验收资料。”，生成并确认纪要，记录 MTG- 编号。

4. 为所选候选填写负责人 `u_emp_001`、未来带时区的截止时间，调整优先级并保存修订。

预期：人工确认前没有正式任务；确认后每个所选候选仅创建一项任务；旧候选版本保留。内置工单和已结束审批也可作来源，但需要本人有权的有效记录，不能使用其他人的业务号。

### T31 任务状态、权限与历史

3. 另建样例，由创建人改派到 `u_mgr_001` 并核对风险；原负责人再次推进应被拒绝。
4. 让无权账号直接打开业务号，检查来源正文不泄露；终态不能编辑或重开。

预期：状态由待开始到进行中、已完成、已归档；改派即时撤销旧负责人的推进权限；过期版本冲突不会覆盖当前记录。

### T32 内部逾期提醒

1. 在隔离测试环境创建带已过去期限的独立样例，保持任务未完成，等待调度扫描。
2. 当前负责人查看“逾期通知”；超过截止时间二十四小时后，创建人可收到升级通知。
3. 标记已读并刷新，记录通知业务号；重复扫描不应重复通知。
4. 完成或取消样例后，观察不再产生新阶段通知。场景关闭或来源权限撤销的组合用例需要测试环境提供，条件不足记“待环境支持”。

预期：仅产生平台私有通知，不发送邮件/OA 通知，不自动改派。自动化已覆盖时间控制、竞态、幂等和扫描轮转，人工等待不能替代这些边界断言。

### T33 登记指标和计划批准

2. 创建计划，核对指标版本、个人范围、时区和日期；未勾选计划确认时不能查询。
3. 明确批准后查看工具返回的表格、图表、查询时间和前期对比；空数据应显示零或无对比。
4. 管理员若选择租户范围，核对当前全域权限；普通用户不可据此获取其他人的记录。

预期：当前只支持日粒度，周/月模板仅预填区间。区间采用上海时区 `[开始日,结束日)`；结束日不计入。审批按创建时间入区间，结果取查询时状态，同业务不同审批版本分别计数。

### T34 摘要修订和平台发布

1. 在 T33 报表编辑定性摘要，例如“统计结果已核对，原因候选仍待人工核查。”，保存并比较历史版本。

3. 核对统计口径和原因候选，勾选两项确认，再显式发布，刷新查看只读结果。

预期：摘要编辑不改变数据快照；原因始终为待核验候选；已发布只表示平台记录完成，不写外部 BI，不能覆盖历史。

预期：四节点审查保留原文和规则快照；演示规则不能表示真实法规判断。合同原文中的“忽略规则”等指令不会改变工具或确认权限。

预期：决定含指定复核人、时间、版本、逐项处理和意见；终态只读。没有改写原合同、签署或外发，人工确认不代表法律效力审核完成。
