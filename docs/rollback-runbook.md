# 回滚操作手册

本手册将应用版本回退、向前修复和独立目标恢复分开处理。M4 只提供本机合成数据证据，生产操作需在目标环境验证后执行。

## 切换前核对

1. 明确 Compose project、服务、数据库、文件卷与当前应用版本；记录脱敏健康检查、故障时间、迁移 head 和最近备份编号。
2. 暂停业务入口和后台写入，验证备份清单、文件及哈希；保留现有数据库和文件卷。
3. 用当前版本的 `assert_application_rollback_compatible(revision, current_heads)` 检查目标应用与实际数据库 head。未知版本、空 head、多 head 或不匹配均拒绝。不要只按“上一个提交”判断兼容。

## 应用兼容时

切换到明确、不可变的已验证应用镜像或源码版本，只更新 backend/frontend 服务，保留数据库和文件卷。全部命令使用显式 `--env-file <受保护配置文件>`、`-p <项目名>`、`-f <配置路径>`。验证 `/healthz`、`/api/readiness`、前端、登录、历史、附件、在办审批、余额、审计及幂等后恢复流量；任一关键项失败即停止开放。

## 应用不兼容时

保留故障现场和业务数据，优先在隔离副本验证向前修复。如果必须恢复，选择独立新空库与新文件目录，先验证备份再导入，核对业务后安排切流。记录源/目标身份、备份编号、四个带时区时间点、数据差异及恢复结论。

禁止执行数据库 downgrade、`down --volumes`、`dropdb`、清空业务表或在原库执行带清理参数的恢复。本地 M4 测试的清理只对该次创建并经过身份复核的临时 project 生效，不能照搬至正式环境。

本次实测和未覆盖项见 [M4 验收报告](../changes/m4-resilience/reviews/m4-verification.md)。
