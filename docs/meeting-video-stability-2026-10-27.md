# 视频会议稳定性排查与验证记录

日期：2026-10-27。

## 原因与修复

| 问题 | 证据与影响 | 修复 |
| --- | --- | --- |
| 后台身份同步误触发退会 | 登录信息每 30 秒刷新；旧 watch 每次返回新数组，即使账号相同也执行退出。回归测试和真实双端测试均复现。 | 分别监听用户 ID 和身份提供方，同账号快照更新保留连接；切换账号仍立即退出。 |
| 页面内刷新销毁视频组件 | 会议详情加载前清空 meeting，导致组件卸载及 SDK 销毁。 | 同一会议刷新时保留组件；切换会议或访问被拒绝时仍清理。 |
| 入会与会议操作数据库死锁 | PostgreSQL 在 2026-10-27 09:36:43.436 UTC 记录事务互相等待：入会先锁会议，另一事务先锁身份。 | 入会采用与会议命令一致的锁顺序：租户身份门锁在会议行锁之前。 |
| 单次状态同步失败就退会 | 状态轮询遇到一次临时错误即销毁 SDK。 | 临时错误先提示并重试，连续三次失败退出；401/403/404 仍立即退出。 |
| 连接等待无边界与 SDK 清理竞争 | 迟到的入会结果及上一组件清理可能影响新连接。 | 入会最多等待 60 秒，退出最多等待 15 秒；增加进度、过期结果保护和共享清理队列。 |
| 腾讯域名偶发 DNS 解析失败 | 后端真实调用 console.tim.qq.com 出现 socket.gaierror，入会接口返回 502。 | 仅 DNS 解析失败延迟 0.25 秒重试一次；持续失败显示明确提示。其他传输错误不重试，避免重复执行云端写操作。 |

## 使用与验证边界

浏览器整页刷新一次后重新加入视频会议，以加载修复。会议页面内部的“刷新”已验证保留连接；浏览器整页刷新会重建页面，需要重新入会。

这次证明的是有限时长的本机双客户端真实腾讯链路。长时间多人会议、跨网络弱网、真实设备兼容性及屏幕共享未由本轮合成设备测试证明；外部网络持续异常仍可能导致连接失败。
