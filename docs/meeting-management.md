# 会议管理说明与验证记录

日期：2026-10-25。适用数据库版本：`0035`。入口：`http://127.0.0.1:5182/meetings`。

## 使用流程

1. 点击“发起会议”，填写主题、议题、开始和结束时间，以及会议地点、在线会议链接，或勾选“启用腾讯视频会议”。选择主持人、记录人和参会人员，可按部门筛选并跨部门选择。
2. 保存草稿后检查安排，再点击“发送邀请”。存在人员时间冲突时可返回修改或确认继续；这属于冲突提醒，不是会议室资源预订。
3. 参会人从会议列表或站内信进入详情，回复参加、不参加或待定。发起人可看到反馈，并修改安排或填写原因取消会议。
4. 发起人或主持人点击开始会议。启用视频的会议显示“加入视频会议”入口；受邀成员须在会议进行中登录入会。结束或取消会议时服务端同步解散腾讯房间。结束后，发起人、主持人或记录人录入会议文本，进入既有纪要工作台生成、修订并确认。
5. 确认后的纪要可供受邀成员阅读。具备业务任务权限的纪要编辑人员可提取任务候选，经人工确认后创建业务任务。

已有的纯文本纪要流程保留在“整理已有会议文本”（`/meeting-texts`）；原纪要详情仍使用 `/meetings/:meetingId`，会议安排详情使用 `/meeting-events/:id`。

## 权限与状态

| 人员或状态 | 规则 |
| --- | --- |
| 发起人 | 管理草稿、发邀请、修改安排、取消会议、查看通知结果及重试失败投递 |
| 主持人 | 已发布后可开始、结束会议，结束后协作整理纪要 |
| 记录人 | 已发布后查看会议，结束后协作整理纪要 |
| 普通参会人 | 查看已发布的受邀会议、反馈参会情况、阅读已确认纪要；备注仅本人和纪要编辑人员可见 |
| 未受邀或其他租户成员 | 无法读取会议及关联纪要；管理员身份不自动赋予会议访问权 |
| 草稿 | 仅发起人可见；取消未发布的草稿后仍保持私有，不发送通知 |
| 已安排 | 可回复、改期、变更人员、开始或取消；变更后邀请版本递增，重新收集反馈 |
| 进行中 | 可结束或取消；不能再次修改安排 |
| 已结束、已取消 | 保留历史；结束后可创建一份关联纪要，不可重新开始 |

需要会议读取或写入授权。主持人和记录人必须具备会议写入权限。停用、撤权及人员移除后，访问与待发送通知重新检查权限。时间包含时区，结束时间必须晚于开始时间；每场最多安排 100 人。列表返回最近 200 条，并按当前待办状态展示。

## 通知与功能边界

发送邀请、更新安排、开始、结束、取消、参会反馈及纪要确认会复用现有业务通知机制。站内信随业务命令在同一事务生成，邮件、企业微信按现有绑定和投递队列处理；外部内容沿用通用 OA 提醒，详情需登录平台查看。

当前本地后端通过 `serve_business_acceptance.py` 启动，业务调度器暂停，外部通知只排队。本次没有向真实邮箱或企业微信群发送会议通知，不能把投递记录中的“待投递”视为已收件。外部真实投递和多人业务试用仍需单独验收。

重试按钮只重排失败的邮件、企业微信记录，保留已送达及结果待核对记录。安排变更使旧邀请版本失效，被移除人员不再能查看原会议；本版没有单独向已移除人员发送退出说明。

传统在线链接仍由用户提供。启用腾讯视频的会议使用 TUIRoomKit 实时音视频界面，入会前由服务端校验租户、受邀身份和会议状态，并仅向该成员签发限时凭证。视频仅在会议开始后开放，会议结束/取消会调用腾讯接口解散房间。当前体验套餐限制实际人数，勿将 OA 的 100 人安排上限理解为腾讯房间容量。实时通话质量、手机媒体兼容性、屏幕共享和多人联调仍需真人浏览器验收。未启用视频的安排保持原行为。AI 关闭时仍可管理会议及反馈，纪要生成和业务任务提取沿用 AI 门禁。

## 实现方案

- `oa_meeting`、`oa_meeting_attendee` 独立保存会议安排与反馈，避免改变历史纪要模型和状态。
- `video_enabled` 为可选开关；腾讯 SDKAppID/SDKSecretKey 保存在后端，UserSig 最长有效 1 小时。视频账号和房间 ID 由租户内用户、会议标识派生，房间密码由后端密钥签发。
- `/api/meeting-events/{id}/video-session` 仅向获准成员提供 no-store 短期凭证；房间按需创建、关闭云端录制，视频模式下结束或取消时同步解散。
- `/api/meeting-events` 提供人员选项、冲突查询、草稿、发布、反馈、状态变化、纪要关联与失败重试。
- 复用现有命令幂等、版本并发校验、业务事件和通知 outbox；服务端按当前身份重新校验权限。
- 关联既有纪要的生成、人工确认及任务候选提取流程；确认前保护草稿，确认后开放受邀成员阅读。

## 维护人员复测

后端只在独立测试库运行，禁止沿用业务库地址。以下命令在专用 PowerShell 终端、`backend` 目录运行，结束后关闭该终端：

```powershell
$env:TEST_DATABASE_URL='postgresql+asyncpg://oa:oa@localhost:5433/oa_business_m3_test'
$env:TEST_DATABASE_SYNC_URL='postgresql+psycopg://oa:oa@localhost:5433/oa_business_m3_test'
$env:TEST_CHECKPOINTER_URL='postgresql://oa:oa@localhost:5433/oa_business_m3_test'
$env:ALLOW_TEST_DATABASE_RESET='true'
& ./.venv/Scripts/python.exe -m pytest tests/api/test_meeting_management.py tests/migrations/test_meeting_management_migration.py tests/api/test_meeting_http.py tests/api/test_meeting_flow.py tests/unit/test_meeting_service.py tests/api/test_oa_notification_targeted.py -q
```

前端目录执行 `npm test -- --reporter=dot` 与 `npm run build`。

`node e2e/verify-meeting-management.mjs` 需要独立库和暂停调度的 8016 后端、代理该端口的 5183 前端，并使用 Mock 模型、关闭 SMTP 和企业微信；会写入独立库的合成会议。不要与会重置该独立库的 pytest 同时执行。

`node e2e/verify-meeting-management-live.mjs` 使用现有 5182/8015 服务，只检查主环境页面及读取接口，创建短期验收会话后撤销，并在浏览器中拦截任何意外业务写请求。
