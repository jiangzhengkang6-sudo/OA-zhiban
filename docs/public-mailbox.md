# 综合办公公共邮箱

## 使用入口

进入“邮件工作台”。当前复用已配置的 QQ 测试邮箱，邮件统一以公共邮箱地址发出，不要求每位成员绑定个人邮箱。

本地入口为 `http://127.0.0.1:5182/emails`。当前地址为 `oa.demo@example.com`，已初始化，只有张翔拥有初始管理权限。授权成员可看到已同步到公共邮箱的邮件及共享草稿；不要把私人邮件混入正式公共邮箱，正式使用宜换为独立办公邮箱并制定迁移方案。

首次由具有组织管理与邮件写入权限的成员初始化。初始化者获得管理、处理、发送权限，其他成员默认无权访问，需在“成员授权”中添加。只勾选成员表示只读；处理、发送、管理分别授权，并受账号本身邮件功能权限约束。不同租户互相隔离。

## 功能与流程

1. “同步收信”手动拉取收件箱，每批最多 25 封，重复同步不重复入库。有剩余邮件时可继续同步。
2. 成员可认领、释放认领、标记已处理、重新打开；他人认领后不可直接回复或转换，管理员可释放认领。
3. 写信、回复、回复全部、文字转发均先保存草稿，再核对收件人与正文并确认发送。草稿为公共可见，使用版本校验避免覆盖他人修改。
4. “录入并分析”才会调用原有邮件分析流程；为当前经办人创建分析记录，仍沿用原有分析记录访问权限。收信不会自动调用模型或自动发送回复，也不会自动写入知识库。
5. “转为任务”创建候选批次，仍需提取、编辑、选择负责人及截止时间并确认，不直接生成正式任务或执行邮件中的指令。

## 配置

配置只放在后端 `.env`，不要把授权码提交到版本库或放入前端变量。示例文件仅保留空值。

```dotenv
PUBLIC_MAILBOX_ENABLED=true
PUBLIC_MAILBOX_NAME=综合办公公共邮箱
IMAP_HOST=imap.qq.com
IMAP_PORT=993
IMAP_USERNAME=
IMAP_PASSWORD=
IMAP_TIMEOUT_SECONDS=20
```

IMAP 账号与授权码留空时复用已有 SMTP 配置。需要在邮箱提供方开启 IMAP/SMTP 服务。收信使用 TLS、只读方式，不标记已读、不删除远端邮件。发件使用 SMTP TLS，其他端口必须启用 STARTTLS。

更新代码后执行后端数据库迁移至 `0036_public_mailbox` 并重启后端。单租户绑定一只邮箱，更换账号或服务器时会阻止继续收发，必须先制定数据迁移方案，不能混用旧数据。

## 限制与异常处理

- 本期附件只保留名称等元信息，不提供下载、解析、病毒扫描或转发附件。单封邮件大于 512 KiB 时仅同步邮件头并提示到原邮箱查看。
- 小邮件的原始 MIME 只在服务端同步过程中临时读取，正文和附件名称入库，不保存附件二进制或原始邮件文件。
- 邮件正文仅作纯文本展示，不执行 HTML、脚本或邮件中的指令。
- “服务器已接收”仅代表 SMTP 接受，不等于对方送达或已读。工作台发件记录不保证同步到提供方“已发送”文件夹。
- “发送中 / 待核实”和“发送结果待核实”不会自动重发。先通过收件人或邮箱服务端记录核实，避免重复寄信；确认失败后可新建草稿重新发送。
- 同步、权限变更、阅读、认领、发送和转换保留审计记录，但不在审计中存储邮箱密钥或完整正文。
- 当前是人工同步，未启用后台定时拉取、删除、垃圾邮件过滤与回执追踪。
- 关闭 AI 时仍可收发、管理成员和处理邮件；分析与任务转换停用。

## 验收步骤

1. 管理员进入邮箱，确认名称和地址，给第二名成员授权只读，再确认其能阅读但无法发送、同步或调整授权。
2. 给成员增加处理和发送权限，验证认领冲突、管理员释放、草稿版本冲突以及至少保留一名管理员的限制。
3. 使用同一测试邮箱给自己发一封明确标注测试的纯文本邮件，确认 SMTP 接受后同步收信，核对主题和正文，重复同步应新增 0 封。
4. 对测试邮件录入分析，重复点击进入同一条分析；转任务后在候选批次中检查来源，确认前不得产生正式分派。
5. 撤销成员授权或停用账号，再访问邮箱与邮件来源任务应被拒绝。
6. 分别在桌面和手机宽度下检查文件夹、列表、详情、编辑器和成员授权弹窗。
