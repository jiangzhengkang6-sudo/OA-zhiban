# P2 会议文本智能体执行契约

## Contract Status

状态：已批准（DP-3，按用户确认执行）。

本契约基于已确认的 proposal.md、specs/meeting-agent.md、design.md 和 tasks.md。未完成 DP-3 前不得修改生产实现代码。

## Intent Lock

在现有 P1 平台底座上新增一个独立的会议文本智能体：输入会议文字，生成带来源引用的纪要、决策和待办草稿，支持人工编辑、确认、拒绝、重新生成、暂停、恢复、重试、权限隔离、幂等和审计；本批确认只保存平台内结果，不接入真实 OA、任务、日历或邮件写入。

## Approved Behavior

1. 有权限用户可以创建、读取和恢复会议文本任务。
2. 系统校验输入非空、长度上限和可解析性，并将文本切分为有序来源片段。
3. 系统生成结构化会议草稿：摘要、议题、决策候选和待办候选。
4. 决策和待办候选必须保留来源片段；没有明确负责人或截止时间时保持待确认状态。
5. 用户可以编辑草稿，编辑产生不可覆盖的新版本。
6. 用户可以确认、拒绝或重新生成草稿；确认和拒绝必须记录操作者、原因、版本和幂等键。
7. 模型或解析依赖失败时任务进入 PAUSED，重试从 Checkpoint 恢复，不重复已完成版本或审计动作。
8. 每次读写操作重新执行租户和资源权限校验；跨租户或撤权后访问必须被拒绝。
9. 所有写命令使用统一幂等机制；相同载荷回放首次结果，不同载荷返回冲突。
10. 审计记录创建、解析、生成、编辑、重生成、确认、拒绝、暂停和恢复，并保留 trace_id。
11. 本批明确 external_writes=false；确认后不得调用任何外部任务、日历、邮件或 OA 写工具。

## Scope Fence

### In Scope

- meeting 场景和会议领域模型。
- 文本输入、分段、来源定位和结构化草稿。
- 会议草稿版本、人工决定和状态机。
- 会议子图、Mock 生成器、Checkpoint 恢复和安全重试。
- REST API、任务中心投影、前端会议工作台、审计入口。
- 单元、API、图、组件、E2E、恢复和权限测试。
- P2 会议验收文档和结果索引。

### Out of Scope

- 音频/视频上传、ASR、说话人分离。
- 真实 OA、任务系统、日历和邮件发送/写入。
- 自动发布纪要、自动承诺事项或对外分享。
- 文档智能体、邮件智能体和 P3 能力。
- 企业 SSO、组织主数据和通用 BPMN 引擎。
- 清空开发数据库、删除 Docker 卷或改变 P1 既有数据。

## Architecture Constraints

- 复用 AgentThread 作为会话和 LangGraph thread_id 主锚点，scene=meeting。
- 会议原文、来源片段、草稿版本和人工决定使用独立模型和迁移保存。
- 会议子图独立文件接入 SuperAgent，不修改 P1 子图的业务语义。
- 使用现有授权、幂等、审计、运行 Span 和 Checkpoint 能力。
- 审计和运行日志只保存脱敏摘要、哈希、数量和定位，不保存完整会议原文。
- 数据库变更只能通过 Alembic；测试必须指向独立 _test 数据库并启用显式清理许可。

## Execution Batches

### M1：领域模型、迁移和文本解析

产出五个会议领域模型、0016 迁移、Meeting DTO、解析器和单元/迁移测试。完成定义：迁移安全、空/超长/多语言文本测试通过，片段可还原原文。

### M2：会议服务、子图和 API

产出状态机、草稿服务、meeting graph、Mock 生成器、会议 REST API、权限/幂等/审计/任务投影。完成定义：正常生成、暂停恢复、确认门禁、跨租户隔离和幂等测试通过，P1 后端全量回归通过。

### M3：前端会议工作台

产出会议 API 类型、页面、草稿编辑器、来源列表、角色入口、任务恢复和审计查询。完成定义：组件测试、生产构建和 P1 角色 E2E 通过。

### M4：验收、恢复和文档

产出 P2 会议 E2E、恢复/安全测试、验收记录和功能实测补充。完成定义：E2E 连续运行稳定，P1 全量回归通过，外部写入边界有证据且文档齐全。

## Test Obligations

- M1：解析器、状态常量、迁移字段/唯一约束和敏感摘要测试。
- M2：会议 API 全流程、权限即时撤销、幂等冲突、图恢复、外部写工具调用计数为零。
- M3：空输入、草稿编辑、来源引用、确认/拒绝、暂停重试和权限菜单组件测试。
- M4：员工创建到确认/拒绝、编辑后重新确认、跨租户、管理员审计和连续两次 E2E。
- 每批必须执行相关 P1 回归；禁止以局部测试通过代替全量回归。

## Review Gates

1. 每个任务先有失败测试，再实现最小代码。
2. 每个批次完成后进行规格符合性和代码质量复核，再进入下一批。
3. 发现需求新增、外部写入、接口权威边界变化、数据模型无法支持版本/授权时，停止实现并回到规划阶段。
4. 任何测试失败、构建失败或行为异常先进入 bug investigation，不绕过失败继续扩展范围。
5. P2 会议 Exit 前不得宣称真实 OA 或外部任务/日历写入已验证。

## Escalation Rules

- 若会议原文需要音频转写，暂停并重新规划，不在本契约内临时加入 ASR。
- 若确认动作需要真实 OA/任务/日历/邮件写入，暂停并新增外部 Provider、对账和上线验收契约。
- 若需要跨用户共享会议，暂停并补充共享授权模型、组织权限和审计要求。
- 若迁移无法在不破坏既有数据的前提下完成，停止执行并回到设计阶段。
- 若同一问题连续三次修复仍失败，暂停当前批次并请求重新评估。
