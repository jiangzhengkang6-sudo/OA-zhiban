# 会议文本智能体规格

## ADDED Requirements

### Requirement: 会议内容创建与输入校验

系统 MUST 允许有权限的用户创建会议任务并提交会议文本；系统 MUST 校验文本非空、长度在配置上限内，并拒绝无法解析的输入。

#### Scenario: 创建有效会议文本任务

- **WHEN** 员工提交非空且未超过上限的会议文本
- **THEN** 系统创建唯一 meeting_id 和任务状态，并返回可恢复的任务详情

#### Scenario: 拒绝空内容

- **WHEN** 用户提交空白文本或仅包含空白字符的内容
- **THEN** 系统返回结构化校验错误，不创建会议任务或草稿

#### Scenario: 拒绝超长内容

- **WHEN** 用户提交超过配置上限的会议文本
- **THEN** 系统返回稳定的输入长度错误，并提示分段提交

### Requirement: 会议内容分段和来源定位

系统 MUST 将会议文本分成可处理片段，并为每个片段保留顺序、字符范围和原文引用；后续纪要、决策和待办草稿 MUST 能回指来源片段。

#### Scenario: 保留来源片段

- **WHEN** 系统完成会议文本解析
- **THEN** 每个片段拥有稳定序号和定位信息，且拼接片段可以还原原始文本顺序

#### Scenario: 草稿引用来源

- **WHEN** 生成摘要、决策或待办候选
- **THEN** 每个结果项包含一个或多个来源片段标识，不允许返回没有来源的确定性业务结论

### Requirement: 结构化会议草稿

系统 MUST 生成可编辑的会议草稿，至少包含摘要、议题、决策候选和待办候选；待办候选 MUST 包含标题、负责人候选、截止时间候选、优先级和来源片段。

#### Scenario: 生成完整草稿

- **WHEN** 有效会议文本解析完成且模型/规则处理成功
- **THEN** 任务进入 DRAFT_READY，返回摘要、议题、决策和待办结构

#### Scenario: 内容不足时保留不确定性

- **WHEN** 会议文本没有明确负责人或截止时间
- **THEN** 对应字段保持空值或标记为待确认，不得自行补全为确定信息

### Requirement: 人工审阅和决定门

系统 MUST 支持用户编辑草稿、确认草稿、拒绝草稿和重新生成；未经确认，系统 MUST 不创建外部任务、日程、邮件或 OA 写入。

#### Scenario: 编辑后重新审阅

- **WHEN** 用户修改摘要、决策或待办字段并保存
- **THEN** 系统保存新的草稿版本，保留修改前版本，并将状态保持为待审阅

#### Scenario: 确认会议草稿

- **WHEN** 有权限的用户以有效幂等键确认当前草稿
- **THEN** 系统记录人工决定并将任务置为 CONFIRMED；本阶段只生成平台内确认结果，不发起外部写入

#### Scenario: 拒绝会议草稿

- **WHEN** 用户拒绝草稿并填写原因
- **THEN** 系统记录拒绝原因和操作者，任务进入 REJECTED，且不得产生外部副作用

#### Scenario: 重新生成草稿

- **WHEN** 用户请求重新生成且当前任务仍可审阅
- **THEN** 系统生成新的草稿版本并保留旧版本和重新生成原因

### Requirement: 权限与租户隔离

系统 MUST 在创建、读取、编辑、确认、拒绝和重新生成的每次请求中重新校验用户权限；用户 MUST 只能访问其租户内且被授予访问权的会议任务。

#### Scenario: 拒绝跨租户读取

- **WHEN** 用户使用其他租户的 meeting_id 请求详情
- **THEN** 系统返回统一无权限错误，不泄露会议标题、内容、草稿或来源信息

#### Scenario: 权限即时撤销

- **WHEN** 用户创建会议后被移除会议访问角色，再请求编辑或确认
- **THEN** 系统拒绝操作，不使用创建时缓存的权限决定

### Requirement: 幂等和并发决定

系统 MUST 使用幂等键保护创建、保存版本、确认、拒绝和重新生成等副作用命令；相同载荷重复请求 MUST 返回首次结果，不同载荷复用同一幂等键 MUST 返回冲突。

#### Scenario: 重复确认只产生一次结果

- **WHEN** 用户以相同幂等键重复确认同一草稿
- **THEN** 系统返回首次确认结果，且不新增决定、版本或审计副作用

#### Scenario: 幂等键载荷冲突

- **WHEN** 用户以已使用的幂等键提交不同确认载荷
- **THEN** 系统返回幂等冲突错误，任务状态和首次结果保持不变

### Requirement: 暂停、恢复和失败重试

系统 MUST 为会议处理保存 Checkpoint；模型或解析依赖失败时 MUST 将任务置为可恢复暂停状态，重试 MUST 从最近安全步骤继续且不得重复已完成的草稿版本或审计动作。

#### Scenario: 依赖故障后暂停

- **WHEN** 会议解析或草稿生成依赖超时或不可用
- **THEN** 系统保存错误码、trace_id 和恢复位置，任务进入 PAUSED，不生成不完整的确认结果

#### Scenario: 重启后恢复

- **WHEN** 服务在任务暂停或待审阅期间重启，用户重新打开 meeting_id
- **THEN** 系统恢复最新状态、草稿版本、待办动作和当前可用操作

#### Scenario: 安全重试不重复处理

- **WHEN** 用户对可重试的暂停任务执行重试
- **THEN** 系统从 Checkpoint 继续，已完成片段不重复生成版本或重复写审计事件

### Requirement: 审计和运行追踪

系统 MUST 记录会议创建、解析、草稿生成、编辑、重新生成、确认、拒绝、暂停和恢复事件；每条事件 MUST 包含操作者、meeting_id、动作、结果、时间和 trace_id。

#### Scenario: 查询会议完整轨迹

- **WHEN** 管理员按 meeting_id 或 trace_id 查询审计中心
- **THEN** 系统返回从输入到人工决定的有序事件，并能区分模型结果和人工决定

#### Scenario: 非管理员查询受限

- **WHEN** 普通用户查询不属于自己的会议审计轨迹
- **THEN** 系统返回无权限错误，不泄露事件摘要或来源内容

### Requirement: 会议结果导出边界

系统 MUST 将确认结果限制在平台内的会议记录和可审阅数据；本阶段 MUST NOT 自动调用外部任务、日历、邮件或 OA 写入工具。

#### Scenario: 确认后不调用外部写工具

- **WHEN** 用户确认会议草稿
- **THEN** 系统只保存平台内确认记录，外部写工具调用计数为零，并在审计中记录本阶段无外部写入
