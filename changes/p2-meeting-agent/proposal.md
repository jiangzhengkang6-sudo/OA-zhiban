# P2 会议文本智能体

## Why

P1 已经提供统一会话入口、权限校验、人工确认、幂等、Checkpoint、审计和降级能力，但目前还不能把会议内容整理成可复核的业务草稿。会议纪要通常包含摘要、决策和待办，若直接依赖人工整理，容易遗漏负责人、截止时间和依据，也无法沿用现有的审计与恢复机制。P2 第一批先实现会议文本智能体，验证内容生产类子图在现有平台底座上的完整闭环。

## What Changes

- 新增会议文本会话入口，支持粘贴或上传文本内容。
- 从会议内容生成结构化纪要草稿，包括摘要、议题、决策和待办候选。
- 待办候选支持负责人、截止时间、优先级和依据片段展示。
- 参会人可以编辑、确认、拒绝或重新生成草稿。
- 所有确认、修改、拒绝和重新生成动作记录审计事件，并支持刷新/重启后恢复。
- 会议草稿默认只保存为平台内的可审阅结果，不自动写入真实 OA、任务系统或日程系统。

## Scope

### In Scope

- 会议文本的新建、保存、读取和权限隔离。
- 会议内容的分段、主题提取、摘要、决策和待办候选生成。
- 结构化草稿展示与人工编辑。
- 确认、拒绝、重新生成和幂等处理。
- 长任务状态、暂停/恢复、失败重试和 Checkpoint 恢复。
- 会议草稿、来源片段、模型结果状态和人工决定的审计记录。
- 员工、管理员和具有会议访问权限用户的前端入口。

### Out of Scope

- 音频/视频上传、语音识别和说话人分离。
- 真实 OA、任务系统、日历或邮件系统的写入。
- 自动代表参会人承诺事项、发布纪要或对外分享。
- 文档起草和邮件智能体。
- P3 合同审查、报表分析和跨域任务自动分派。
- 企业 SSO、组织主数据和通用 BPMN 流程引擎。

## Impact

### Backend

- 新增会议会话、会议草稿、决策候选、待办候选和确认记录的数据模型与 API。
- 新增会议子图，复用现有会话、权限、幂等、Checkpoint、审计和运行观测服务。
- 新增会议输入长度、敏感信息和内容状态校验。

### Frontend

- 新增会议入口、内容编辑器、纪要/决策/待办草稿卡片和人工确认操作。
- 在任务中心、审计中心和运行观测中展示会议任务状态与 trace。

### Verification

- 单元测试覆盖结构化抽取和状态机。
- API 测试覆盖权限、幂等、确认门禁、编辑重审和恢复。
- 前端组件/E2E 覆盖员工创建、草稿编辑、确认/拒绝和管理员审计入口。

## Capabilities

- meeting_ingest：保存并解析会议文本。
- meeting_draft：生成纪要、决策和待办草稿。
- meeting_review：编辑、确认、拒绝和重新生成。
- meeting_recovery：暂停、恢复、重试和幂等恢复。
- meeting_audit：记录内容来源、模型结果和人工决定。

## Success Criteria

1. 用户可以创建会议文本任务，刷新或重启后仍可恢复同一任务。
2. 系统生成的纪要、决策和待办均为可编辑草稿，并保留来源片段。
3. 未经人工确认，不产生外部任务、日程、邮件或 OA 写入。
4. 同一确认请求重复提交不会生成重复记录；修改已处理请求会返回冲突。
5. 权限不足不能读取其他用户或其他租户的会议内容。
6. 模型/工具故障时任务可暂停并安全重试，不重复已完成步骤。
7. 审计可以按会议任务、业务 ID 或 trace ID 查询完整轨迹。
