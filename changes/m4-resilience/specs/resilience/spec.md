# M4 安全与恢复规格

## ADDED Requirements

### Requirement: 演练环境必须隔离

M4 自动化演练 MUST 使用专用 Compose project、数据库和持久化卷，并在启动前核对其目标为隔离环境。演练 MUST 使用合成数据，不得读取、覆盖或清理现有 M1/M2/M3 预览数据库、卷、附件或凭据。目标不符合白名单时，演练 MUST 在任何写入或删除动作前失败退出。

#### Scenario: 误指向已有预览数据库

- WHEN 演练配置的数据库主机、数据库名、Compose project 或卷与隔离白名单不符
- THEN 演练在迁移、恢复、写入或删除前失败，并报告不含凭据的原因

#### Scenario: 使用已占用的预览卷

- WHEN 隔离演练发现其声明的卷已由非本次隔离 Compose project 创建或挂载
- THEN 演练拒绝继续，且不移除或修改该卷

### Requirement: 备份覆盖范围完整且可校验

系统 MUST 提供可重复的备份流程，覆盖 PostgreSQL 业务数据及 LangGraph 检查点、附件文件、知识源文件和非敏感配置清单。每个备份集 MUST 有可验证的完整性清单和生成时间；密钥 MUST 与数据备份分离并采用独立加密保管，不得写入仓库、普通配置清单或演练报告。本地同机备份 MUST 明确标记为演练副本，不得标记为异机备份。

#### Scenario: 备份覆盖所有受管持久化数据

- WHEN 隔离环境生成备份
- THEN 清单列出数据库/检查点、附件、知识源及非敏感配置项，并且每项均可进行存在性和完整性校验

#### Scenario: 备份集被篡改或不完整

- WHEN 恢复前完整性校验发现文件缺失或校验值不一致
- THEN 恢复流程拒绝导入该备份集，并记录失败状态，不修改目标数据库或文件

#### Scenario: 密钥出现在输出或归档

- WHEN 执行备份或生成报告时发现密钥类变量、口令或令牌
- THEN 输出和归档对其脱敏或排除，且独立密钥保管要求明确可审查

### Requirement: 恢复必须写入独立目标并核对业务

恢复流程 MUST 要求显式指定经隔离校验的空白/临时目标，MUST 在写入前验证目标身份和备份完整性。恢复后 MUST 验证登录、历史记录读取、附件下载、在办审批继续处理、知识源可用和检查点/业务表一致性；对已完成操作的重放 MUST NOT 产生重复业务写入。

#### Scenario: 恢复到专用空目标

- WHEN 选择有效的隔离恢复目标并提供有效备份
- THEN 数据库、检查点、附件和知识源均恢复到独立目标，且业务核对项目通过或逐项报告失败

#### Scenario: 恢复目标指向源库或非空未知库

- WHEN 目标与备份源相同、属于受保护数据库，或其身份/状态无法确认
- THEN 流程在执行清理或导入前拒绝恢复

#### Scenario: 恢复后重放已完成审批

- WHEN 在恢复后的隔离环境重放恢复前已成功的审批命令
- THEN 权威业务记录、余额、审计及通知发件箱不产生重复副作用

### Requirement: RPO 与 RTO 必须基于实测

每次恢复演练 MUST 记录备份时间、故障/恢复点、恢复开始与服务可用时间、数据核对结果、RPO 和 RTO 计算口径。报告 MUST 对照 PRD 目标 RPO≤24 小时、试点数据量下 RTO≤15 分钟，注明演练数据量、硬件和环境；未达到目标或缺少证据时 MUST 标记未通过/未覆盖，不得宣称已达标。一次本地演练 MUST NOT 作为持续每日异机备份或每周恢复能力的证明。

#### Scenario: 恢复演练达到目标

- WHEN 记录完整且计算出的 RPO/RTO 不超过目标
- THEN 报告包含测量数据、环境边界和通过状态

#### Scenario: 恢复超出目标或无法测量

- WHEN 任一目标超限或关键时间/数据证据缺失
- THEN 报告将该项标为失败或未覆盖，且不把恢复目标描述为已满足

### Requirement: 升级与回退不得破坏业务数据

部署演练 MUST 验证镜像构建、配置校验、数据库升级、健康检查和应用版本回退。生产式配置 MUST 拒绝弱默认数据库口令和不安全的 Mock 身份/OA Provider 组合。含新业务数据的数据库 MUST NOT 通过破坏性降级回退；数据库迁移不兼容时 MUST 使用独立恢复目标或经验证的向前修复方案，并记录应用与数据库版本关系。

#### Scenario: 配置含弱默认值

- WHEN 启动配置保留默认数据库口令或在生产模式启用 Mock 身份/OA Provider
- THEN 配置校验或服务启动失败，并给出不泄露敏感值的错误

#### Scenario: 升级后兼容应用回退

- WHEN 新版本迁移完成后将应用回退到声明兼容的上一版本
- THEN 应用健康检查通过，已有业务数据保持可读写且关键流程回归通过

#### Scenario: 上一应用版本不兼容新数据库结构

- WHEN 回退检查发现旧应用不能安全使用当前数据库结构
- THEN 流程阻止切换流量到不兼容版本，并指导使用前向修复或独立目标恢复，不执行破坏性数据库降级

### Requirement: 安全边界与审计必须通过验证

M4 MUST 执行提示注入、越权工具/资源访问、外发边界、敏感日志泄漏和审计原子性检查。失败的业务操作 MUST NOT 被记录为成功；关键写操作成功与审计记录 MUST 保持既有原子性约束。任何测试 MUST 使用隔离数据和 Mock 外部依赖，不得产生真实外发或付费模型调用。

#### Scenario: 提示注入诱导越权或泄露

- WHEN 恶意文档/用户输入要求忽略策略、调用未授权工具或返回无权数据
- THEN 请求被拒绝或转人工，且无未授权数据进入响应、日志或外发载荷

#### Scenario: 越权读取附件或业务记录

- WHEN 无权用户通过接口、工具或恢复后的会话读取他人私有资源
- THEN 系统拒绝访问且响应不泄露资源正文或敏感存在性信息

#### Scenario: 业务写入失败

- WHEN 关键业务事务失败
- THEN 审计记录不标记操作成功，业务状态与成功审计不会部分提交

### Requirement: 降级路径保持人工业务可用

系统 MUST 在 AI 关闭时保留手工发起、确定性校验、审批、查询和审计能力，且不得删除图状态。本体故障演练 MUST 使用备用人工记录流程，并在恢复后按操作者、业务对象和版本进行补录与对账；AI 关闭 MUST NOT 被当作本体故障恢复方案。

#### Scenario: AI 提供方故障后关闭 AI

- WHEN AI 调用不可用且管理员关闭 AI 路径
- THEN 用户仍可通过人工入口办理允许的业务操作，权限校验、确定性规则及审计继续生效

#### Scenario: 本体暂时不可用

- WHEN 本体不可用导致业务命令无法提交
- THEN 用户可按演练手册记录备用人工事项；本体恢复后可逐项补录、去重并核对最终状态
