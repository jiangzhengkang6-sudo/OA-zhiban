# M4 技术设计

## Context

M1–M3 已完成本地工程范围的业务实施与验证，M4 需验证安全、备份、恢复、降级、镜像、配置和数据库迁移。现有 Compose 文件使用固定容器名、默认数据库凭据和 Mock Provider 默认值；应用容器启动会执行 Alembic upgrade。业务表与 LangGraph checkpoint 共用 PostgreSQL；附件、知识源、审计导出为由独立配置目录控制的本地文件存储。部署/回滚文档尚未附隔离恢复实测记录。

约束：服务器迁移在 V2；M4 只使用本机隔离 Compose project、临时数据库与卷、合成数据。不得读取或改变既有预览数据库、卷、凭据与 `.env`，不得连接真实外部服务或调用付费模型。M4 不能将单次验证描述为持续异机备份或生产上线证明。

## Goals

- 证明演练目标严格隔离，错误目标在任何变更前失败关闭。
- 证明 PostgreSQL 与受管文件可备份、校验、恢复到独立目标，并通过核心业务核对。
- 用实际时间和数据点计算 RPO/RTO，保留环境参数和可重现证据。
- 验证镜像配置、数据库升级、兼容应用回退、AI 关闭人工路径、安全边界和本体故障后的补录对账。
- 将尚未具备运行基础设施的异机副本、定时告警和持续每周演练明确列为未覆盖项，不用本地证据替代。

## Decisions

### D1: 所有演练通过独立运行身份和目标白名单

**Choice:** 每次演练使用唯一 Compose project 名、独立容器/网络/卷、隔离数据库名及专用文件根目录。移除或避免依赖固定容器名。演练入口在运行 Docker 或数据库写操作前核对显式演练标志、project 身份、数据库主机/名称、卷归属和文件根目录；目标身份不明确或落入受保护资源时立即退出。所有测试使用合成 fixtures。

**Rationale:** 现有 Compose 固定容器名会与并行预览冲突，且仅靠数据库名不足以保护文件卷。先验目标再执行副作用可避免测试便利逻辑误删既有状态。

**Alternatives considered:** 复用现有开发 Compose project 或仅依赖 `ENVIRONMENT=test` 不足以隔离卷和文件目录；手工口头确认目标不能作为自动化保护，因此不采用。

### D2: 数据库和文件采用分层备份集

**Choice:** 使用 PostgreSQL 自定义格式逻辑备份保存业务表与 checkpoint 表；单独归档设置中实际启用的持久化文件目录，包括附件、知识源和审计导出，并按需包含隔离 Mock 状态文件。生成非敏感 manifest，记录备份时间、目标组件、相对路径、文件大小和 SHA-256。备份在恢复前整体校验，任一项缺失/不符即拒绝恢复。演练数据不包含真实凭据；如测试密钥用于密钥流程验证，只使用临时合成值，密钥材料不得与备份集共同归档。

**Rationale:** `pg_dump` 不能保存数据库外的文件对象；文件引用存在于数据库，必须使用同一备份集快照并在恢复后校验引用对象。哈希能发现缺失和损坏，但不提供机密性或真实性认证，因此不把校验和宣称成加密。

**Alternatives considered:** 只备份 PostgreSQL 会遗漏附件/知识文件；只打包整个 backend 目录会混入代码、缓存及可能的敏感配置；逐项使用明确配置的持久化目录更易审计。

### D3: 恢复使用新建的空白目标，不原地清理

**Choice:** 演练先建立独立恢复数据库、Compose project 和文件根目录，再恢复数据库与文件。恢复工具必须验证目标不是源库、不是受保护资源且为空；不使用 `--clean` 清理未知目标，不允许从演练入口删除原卷。恢复后执行健康检查、权限登录、历史记录读取、附件下载、知识文件读取、在办流程继续、checkpoint 与业务状态对账及已完成命令幂等重放。

**Rationale:** 新目标恢复能保留故障现场和源备份，避免把“恢复测试”变成不可逆覆盖操作。功能级核验比单纯检查数据库进程启动更能证明业务可恢复。

**Alternatives considered:** 原地 `pg_restore --clean` 操作步骤短但会先销毁目标状态，目标选错时影响不可逆，因此禁止用于本演练。

### D4: RPO/RTO 以可复核的时间边界计算

**Choice:** 报告记录数据基准时间、备份完成时间、模拟故障时间、恢复启动时间、核心功能全部核验可用时间，以及演练数据量/附件大小/硬件。RPO 按故障时点与恢复后最后一个可验证业务提交的差值计算；RTO 按模拟故障至全部核心核验通过的时长计算。目标按 PRD 的 RPO≤24 小时、试点数据量 RTO≤15 分钟比较。缺少时点或核验项时标记未覆盖。

**Rationale:** PRD 要求分别统计备份频率与恢复目标；容器启动时间不能代表业务服务恢复完成。

**Alternatives considered:** 以最近备份年龄代替 RTO，或以 `/healthz` 单接口可达代替业务恢复，均无法反映可用数据与实际审批能力，不采用。

### D5: 生产式配置校验失败关闭，迁移不做破坏性降级

**Choice:** 保持开发预览可显式使用 Mock，但生产模式必须拒绝弱/缺省数据库口令、Mock 身份或 OA Provider、不安全 Cookie 来源和不符合生产要求的配置。部署验证先检查配置和 Compose 展开结果，再构建镜像，执行升级并检查 readiness。回退只允许到明确标记兼容当前 schema 的应用版本；若 schema 不兼容，阻止应用切换，采用前向修复或在独立恢复目标恢复，不执行数据库 downgrade 或清卷。

**Rationale:** 现有启动配置有方便开发的默认值，不能把它们原样带入正式式部署。Alembic 自动升级导致应用回退与数据库结构版本必须联合评估。

**Alternatives considered:** 全局删除 Mock 默认会破坏现有本地开发流程；保留默认且仅靠部署手册提醒风险不构成有效保护。采用按运行环境区分的显式校验。

### D6: AI 降级与本体故障采用不同演练路径

**Choice:** AI 依赖故障时演练关闭 AI 开关并使用现有人工业务入口；本体不可用时不把 AI 开关当作恢复措施，而使用人工记录模板记录操作者、对象、版本、时间和待办动作，本体恢复后逐项校验权限、去重补录并对账。演练只使用本地合成数据，不向外部渠道发送通知。

**Rationale:** PRD 明确 AI 关闭不能替代本体恢复；两类故障的业务责任与恢复动作不同。

**Alternatives considered:** 两种故障统一显示“降级模式”会掩盖本体权威数据不可用，不能保证人工补录一致，因此分别记录与验收。

### D7: 演练证据限定结论等级

**Choice:** 报告记录命令/测试、镜像与迁移版本、目标标识（不含密钥）、日志位置、结果、RPO/RTO 计算和未覆盖项。演练可验证本机备份/恢复流程，不实现或宣称异机副本、每日调度告警、持续每周恢复或生产可用性；这些依赖 V2 目标环境和另行验收。

**Rationale:** PRD F-151/AC-D7 对异机与周期性能力有明确要求，而本地单次试验不具备证明它们所需的环境和时间跨度。

**Alternatives considered:** 将本地不同目录称为异机备份会夸大故障域隔离；把目标写成通过项会造成错误上线判断，均不采用。

## Risks And Trade-Offs

| 风险 | 控制措施 |
| --- | --- |
| 演练误连现有预览数据库或卷 | 独立 project/资源名前缀，数据库与卷白名单，执行前只读核验；拒绝未明确身份的目标 |
| 数据库和文件归档时点不一致 | 暂停隔离环境写入后生成同一备份集；manifest 记录采集区间，恢复后核验数据库引用文件完整 |
| 哈希清单被替换或不提供加密 | 报告仅说明完整性校验；密钥独立加密保管，真实密钥完全排除于本地演练 |
| 自动迁移阻塞启动或不兼容旧应用 | 单独验证升级、readiness 和声明兼容的应用回退；schema 不回退，保留前向修复/独立恢复路径 |
| AI 关闭误当作本体灾备 | 两种故障单独演练，人工记录与恢复后对账留证 |
| 本地证据被误读为生产认证 | 报告明确演练数据/硬件/依赖范围及异机、周期性恢复的未覆盖状态 |
