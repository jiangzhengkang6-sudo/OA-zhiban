# M4 安全与恢复演练

## Why

M1–M3 已完成本地工程功能验证，但项目尚未证明在配置错误、部署升级失败、数据损坏或智能能力不可用时能够安全运行并恢复。现有部署与回滚文档描述了操作步骤，尚缺少隔离环境中的可复现证据。M4 需要补齐安全检查、备份覆盖、隔离恢复、降级与升级/回退演练，作为验证版交付门槛；这不等于生产上线或服务器迁移批准。

## What Changes

- 建立可重复的本地隔离演练流程，覆盖镜像构建、配置校验、数据库迁移、备份、恢复、应用回退和恢复后业务核对。
- 验证备份范围包含 PostgreSQL 业务数据与 LangGraph 检查点、私有附件、知识源文件及非敏感配置清单；密钥与数据备份分开管理，不写入仓库或演练报告。
- 针对提示注入、权限边界、外发控制、敏感日志、审计完整性和安全配置默认值执行检查，并记录可复现结果。
- 演练关闭 AI 的人工办理路径，以及本体故障时备用人工记录、恢复后补录和对账流程。
- 记录隔离恢复实测 RPO/RTO、升级与兼容应用回退结果、缺陷及限制；不得将目标值写成未实测的保证。

## Scope

### In

- 仅使用本机隔离的 Docker Compose 环境、专用临时数据库/卷和合成数据；与 M1/M2/M3 预览数据库及数据卷分离。
- 可复现的安全与配置校验、镜像构建、迁移、备份、隔离恢复、回退和降级演练，以及对应测试、操作说明和证据报告。
- 以 PRD V1.5 F-151 和 AC-G1–AC-G5 为验收基线。恢复目标按实测记录，参考 RPO≤24 小时、试点数据量 RTO≤15 分钟；演练条件和计时边界一并记录。
- 识别备份加密和异机副本的实现要求；本地演练只验证可配置性与流程，不将同机副本宣称为异机备份。

### Out

- 生产或共享服务器部署、DNS/HTTPS/防火墙调整、真实组织/试点数据导入及服务器迁移；这些仍属于 V2，须另行授权。
- 连接真实 SMTP、OA、IM、文件扫描或其他外部服务，发送真实通知，或产生真实模型/嵌入调用费用。
- 读取、复制、改写或迁移现存 `.env`、真实密钥，以及 M1/M2/M3 数据库、卷和预览账号。
- 将本地备份冒充异机备份，或仅凭一次演练宣称达到持续每日备份、每周恢复和生产可用性目标。
- 与 M4 验收无直接关系的业务功能扩展、组织深化和 UI 改造。

## Impact

- `docker-compose.yml`、Dockerfile、应用启动/健康检查、Alembic 迁移、附件/知识源/检查点存储和现有安全相关测试可能需要调整。
- `docs/production-deployment.md` 与 `docs/rollback-runbook.md` 可能需要修订为经演练验证的步骤，并增加隔离恢复及演练报告。
- 任何需触及现存预览数据库、非临时卷、外部服务或真实凭据的步骤必须排除在自动化演练之外。

## Capabilities

- 可在隔离环境生成可校验的备份，并在独立恢复目标中恢复应用所需数据。
- 恢复后可登录、读取历史记录、下载附件、继续审批，并核对检查点与业务权威数据；不得重复执行已完成的写操作。
- 数据库含新业务数据时不执行破坏性降级；回退采用兼容应用版本或前向修复，并以独立恢复目标验证恢复流程。
- AI 关闭时人工办理、校验、审批、查询与审计仍可用；本体故障演练有备用人工记录和恢复后对账证据。
- 安全检查和演练报告能够区分通过、失败、未覆盖与环境限制，不泄露敏感信息。
