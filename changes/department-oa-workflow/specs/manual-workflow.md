# M2 行为规格

状态：2026-10-18 用户已批准。编号同时用于设计、任务和执行契约覆盖校验。

## ADDED Requirements

### Requirement: M2-01 正式人工业务权威

系统 MUST 为 builtin 身份提供独立的人工 OA 领域服务和 `/api/oa` 接口，业务事实仅从同租户正式表和 M1 身份读取；模型、MockAdapter、AgentThread 和 LangGraph 不得决定业务成功。AI 关闭时 MUST 不初始化图运行期且保留检查点；旧 Mock API 的语义和生产 Mock 门禁保持。

#### Scenario: 关闭 AI 和外部适配器

WHEN AI_ENABLED=false，模型及 Mock/外部 OA 调用被测试替身设为调用即失败，且图运行期不可用；THEN 真实账号仍可手工创建、提交、审批和查看单据，服务不读取这些依赖，不删除既有图状态；依赖图的智能入口明确返回不可用。

### Requirement: M2-02 发布验证与版本固定

系统 MUST 发布不可变的流程版本，内含独立版本号和哈希的表单字典、规则及节点定义；支持审批/抄送、指定人/直属上级/角色选择器和前向条件分支。分支运算 SHALL 仅接受声明字段及白名单比较，类型/天数可用于请假；金额运算用精确十进制，只有声明金额字段的表单才可引用。未知字段、非法表达式、循环、不可达/缺失终点、无默认分支及未发布版本 MUST 拒绝。实例固定提交时的三个版本和已解析路线，发布新版本不改旧实例。

#### Scenario: 发布和后续变化

WHEN 发布包含环、未声明 amount 字段或非法表达式的请假流程；THEN 发布失败且旧发布版本保持。WHEN 有效版本已产生在办实例后修改模板或组织；THEN 旧实例版本及处理人不静默改变，资格失效按 M2-09/M2-10 处理。

### Requirement: M2-03 不可变提交与重提

系统 MUST 区分草稿修订号、提交版本和实例路线修订号；仅申请人可编辑可编辑态草稿。成功提交创建不可变表单及附件清单快照并开启新实例；驳回/取消后重新提交 MUST 使用新提交版本，重新预检、占用、解析路线，保留每轮差异。校验失败不创建半成品提交版本；有效表单无合法路线可提交为暂停并占用余额，允许申请人撤回。

#### Scenario: 驳回后再提交

WHEN 第一轮被驳回，申请人改动日期并提交第二轮；THEN 第一轮材料、决定、台账及路线不变，第二轮有新的版本和实例。WHEN 两个客户端同时修改同一草稿修订；THEN 只有一个成功，另一方收到当前修订冲突。

### Requirement: M2-04 日历日、冲突和余额台账

系统 MUST 采用 Asia/Shanghai 业务日期、含首尾的整日规则，拒绝倒置/非法日期，起止同日计一天；跨年按各年度日期拆分额度。每租户/人员/假种/年度账户 MUST 使用整数天数且满足 total >= used + reserved >= 0；未初始化额度不得视为无限或自动补齐。提交占用、批准占用转已用、驳回/撤回释放 MUST 各生效一次并保留台账。该人员不同假种/年度的并发提交 MUST 串行验证日期区间，审批中、暂停和已通过申请均参加含边界的重叠检查。管理员额度调整 MUST 保留原因与前后值，不能低于已用加占用。

#### Scenario: 并发和跨年

WHEN 可用额度为 3 天，两项各 2 天的无重叠申请并发提交；THEN 最多一项占用成功。WHEN 两项不同假种同日申请并发提交；THEN 最多一项成功。WHEN 12 月 31 日至次年 1 月 2 日提交；THEN 两年度分别占用 1、2 天，任一账户不足时整体不占用。WHEN 重复驳回或撤回；THEN 不重复返还。

### Requirement: M2-05 私有附件和版本引用

系统 MUST 仅接受真实上传后、属于本申请的附件 ID；文件字节私有存储、验证 MIME/扩展名/大小/内容/哈希，并记录扫描状态。扫描未配置、失败或未完成 MUST 不等同 CLEAN；模板要求的材料或已引用附件未通过扫描时不得提交。已提交清单 MUST 不被替换；审批读取只能取得被授权轮次清单，跨租户/跨单引用和下载必须拒绝。移除草稿引用不删除历史材料。

#### Scenario: 引用和扫描

WHEN 提交他人附件 ID、未知引用、扫描 PENDING 或被篡改的文件；THEN 提交失败且不占用余额。WHEN 转办后原处理人下载附件；THEN 按最新授权拒绝，不使用旧链接或旧节点资格放行。

### Requirement: M2-06 顺序、会签、或签与抄送

系统 MUST 支持依次激活审批节点，单签仅一个席位，会签全部有效席位同意后推进、任一驳回结束该轮，或签第一次有效同意/驳回决定节点结果并失效其他席位。选择器 MUST 去重，空审批人或自审不得自动通过；同一有效人员不得占会签多个独立席位。抄送 MUST 不产生决定权限，并按激活时点产生收件记录。

#### Scenario: 会签和或签

WHEN 两名会签人分别同意；THEN 第一项仍在办理、第二项才推进。WHEN 或签同意和驳回并发；THEN 仅一个有效决定，后到请求取得可见的当前结果或明确冲突，余额结算一次。WHEN 只有抄送资格者决定；THEN 拒绝。

### Requirement: M2-07 幂等与数据库并发裁决

系统 MUST 持久化操作键及规范化载荷摘要。提交键包含租户/单据/目标提交版本/操作编号，决定键包含租户/实例/节点/操作编号，并绑定操作者；同键同载荷在重新授权后返回原结果，同键异载荷拒绝。状态/修订号与唯一约束 MUST 在数据库中裁决，不能依靠进程内锁；未完成事务的业务、操作结果和台账不得部分可见。

#### Scenario: 丢响应后重试

WHEN 提交已提交数据库但响应丢失，重启后用同一键和载荷重试；THEN 返回原版本/实例，不重复占用或创建事件。WHEN 使用同键改成不同动作或材料；THEN 返回 409。WHEN 两个进程使用同键并发；THEN 只有一份成功记录。

### Requirement: M2-08 状态、受限编辑与归档

系统 MUST 区分草稿、审批中、暂停、通过、驳回和取消，并将归档属性与审批结果分别保留。申请人可撤回审批中/暂停申请；终态和已归档申请不得继续决定。驳回 MUST 有结构化原因与说明；编辑后批准仅允许独立的非关键审批补充说明。日期、类型、申请人和附件等关键字段变化 MUST 退回申请人确认，通过新版本重新校验和路由，审批端不得暗改。归档仅适用于终态并不改变余额。

#### Scenario: 撤回与审批竞争

WHEN 申请人撤回与最后批准并发；THEN 数据库只形成一个终态，批准扣减或撤回释放只执行对应的一种。WHEN 审批端直接修改日期后批准；THEN 拒绝；使用退回修改动作后申请人可编辑重提。WHEN 归档已批准申请；THEN 仍保留批准结果及已用额度。

### Requirement: M2-09 当前身份与节点最小授权

系统 MUST 在接口、领域服务、后台和提交前复核当前身份、权限和范围；本人/本部门读取、有效节点材料上下文及抄送范围分别校验。部门读取权、历史处理记录或抄送 MUST 不赋予决定权；决定要求对应资源写权限及当前有效席位。节点授权只暴露本轮所需字段和附件，不暴露余额账户、其他申请或其他轮次材料。人员停用、调岗、角色失效后 MUST 立即失去不再满足条件的权限，不自动替换处理人。

#### Scenario: 禁用与跨部门

WHEN 审批人停用或岗位/权限变化导致资格失效，旧页面仍发起决定；THEN 决定失败、无业务副作用，实例暂停或显示待管理员处理。WHEN 有效审批人位于另一部门；THEN 可看本节点所需材料，不能列出该部门其他请假或导出余额。WHEN 同租户部门管理者试图访问其他部门单据；THEN 拒绝。

### Requirement: M2-10 代理、转交与显式恢复

系统 MUST 允许具有相应部门流程管理权限的管理员逐席指定代理、转交禁用人员待办或恢复暂停路线，记录理由、前后有效人、节点及路线修订。接收人 MUST 同租户、启用、有办理权限、非申请人且不重复占会签席位；显式替代虽可改变原选择结果，接收范围仍限申请人当前部门或原发布版本显式指定的跨部门候选，不允许任意跨部门转交或链式委托。转交不得复制待办或改变已完成决定。M1 handoff_pending MUST 仅在 M2 可处理的待办已核对完成后按明确范围记录，不将其他业务交接误报完成。

#### Scenario: 转交后旧页面

WHEN 管理员将停用审批人的待办转交合格员工；THEN 新人出现一个有效待办，旧人不能继续办理，快照历史保留。WHEN 转交接收人为申请人、已占会签席位或其他租户；THEN 整体拒绝。WHEN 恢复暂停实例；THEN 使用已固定流程版本的显式路线修订，不套用新模板。

### Requirement: M2-11 超时、重启和对账

系统 MUST 从持久化有效节点扫描催办/升级，使用数据库认领和稳定事件键，多进程/重启不得重复推进；终态不再提醒。超时升级按固定规则查当前合格上级，每席最多自动升级一次；缺上级、自审、重复席位或失效代理时 MUST 暂停并产生管理员事件，不默认通过。恢复/对账 MUST 根据业务、节点和台账校验，不以图状态或通知受理推断成功；发现不一致仅报告、暂停，未经决策不得自动修改财务/余额台账。

#### Scenario: 重启和定时器竞争

WHEN 服务在截止时间后重启或两个调度进程同时扫描；THEN 每个提醒/升级只产生一个业务事件。WHEN 最后决定与调度竞争；THEN 终态不再升级或新增有效催办。WHEN 余额汇总与台账不一致；THEN 给出脱敏异常报告并暂停相关继续处理，不自动赠送/扣减额度。

### Requirement: M2-12 业务、审计和通知事件原子性

系统 MUST 在一个数据库事务内持久化业务状态、节点/席位、余额台账、幂等结果、带租户的业务审计和通知发件箱事件；任一写入失败整体回滚。事件 MUST 具有去重键、当前授权收件人和待发送状态，不存密钥/口令/令牌或敏感材料原文。M2 不实际外发，UI MUST 不将事件已保存显示为已送达；M3 渠道发送失败不得逆转已完成审批。

#### Scenario: 审计或事件写入失败

WHEN 在最后批准中注入审计或 outbox 写入失败；THEN 状态、席位、余额与操作结果一起回滚，可用原键重试。WHEN 事件成功持久化；THEN 显示“待发送”并保留关联单据/版本，未宣称邮件已发送。

### Requirement: M2-13 中文人工工作台与隔离验证

系统 MUST 提供我的申请、待办、已办、抄送、详情/历史、额度管理和流程/异常管理入口；按权限展示当前允许操作、处理人及暂停原因。普通用户 MUST 不需要填写 JSON，不出现原始节点码或规则表达式。列表/直达/附件权限一致，移动端无阻断操作的溢出。验收 MUST 使用独立测试库、Mock 模型与嵌入，覆盖 AI 关闭、迁移保留 M1 和旧 Mock 回归，不修改真实配置或映射历史人员。

#### Scenario: 人工端到端验收

WHEN 真实本地测试账号在桌面及手机完成提交、会签、驳回重提、转交、撤回和归档；THEN 页面与后端一致，只有允许操作可用，故意直连接口仍校验权限。WHEN 运行全部相关回归；THEN M1 会话/组织和显式 Mock 旧流程保持，报告真实命令、结果及限制，不借用历史通过数。
