# B6 中文正式 OA 工作台实施者复核

日期：2026-10-20。结论：B5 依赖已通过，B6 的组件、构建和 M3 预览浏览器证据通过。由当前实施者复核，非独立审查；仓库没有可用 Git HEAD，不虚构 SHA、工具 guard 或机器收据。

## 实际改动范围

- 新增报销工作台，支持草稿、新建、保存、发票上传、提交审批、撤回、归档、审批流程选择和历史展示。
- 新增正式工单工作台，支持本人/处理列表、重复工单候选检查、确认创建、领取、开始办理、完成、分派、负责人、合并请求和反馈展示。
- 新增通知与站内信工作台，支持未读消息、标记已读、投递状态、`UNKNOWN` 邮件人工核对与重试，以及邮件授权配置。
- 扩展正式 OA 类型、API、路由、权限、菜单和旧请假/审批页面的可选流程字段兼容。
- 保留 Element Plus 交互约定和中文业务文案；AI 关闭时仍可通过人工工作台办理。

## 复核结果

报销新建状态已明确区分于已有单据，点击“新建报销”后会显示流程选择和表单；已有单据继续按服务端 `allowed_actions` 控制保存、提交、撤回和归档。工单和通知页面按权限控制请求与操作入口，前端不会以隐藏菜单替代后端授权。投递状态中的 `UNKNOWN` 不会被误报为成功，人工核对和重试使用服务端接口。

## 浏览器复核

M3 独立预览使用 `5195/8015`、专用预览库、Mock 模型/嵌入、关闭 AI、关闭 SMTP 和文件扫描。`b7-business-browser-2.log`：桌面 4 项、390px 手机 4 项，共 8 项通过。

- 中文菜单可进入报销、工单、通知工作台。
- 员工可创建/修改报销、上传有效 PNG；扫描状态为 `PENDING` 时提交被服务端拒绝并保持草稿。
- 员工确认创建工单，管理员办理后可刷新读取持久化站内信并标记已读。
- 员工不能进入审批管理或读取投递管理接口；截图已检查无横向溢出和文字遮挡。

## 已知限制

- 当前验证沿用 M3 测试环境和 Mock 模型/嵌入配置，不代表真实 SMTP、真实生产身份、外部 OA 或生产数据已接通。
- 浏览器只验证了待扫描发票的阻止提交；真实扫描服务、发票真伪校验、完整金额分支和正式审批闭环由后端套件覆盖，未在本地预览中接入外部服务。
- 构建仍会输出既有体积和导入提示；不影响本批功能，但可在后续维护批次优化。
- Element Plus 图标解析和 Vue Router 测试环境警告仍存在，当前没有失败。
