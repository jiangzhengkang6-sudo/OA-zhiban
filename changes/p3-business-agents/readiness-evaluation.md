## Independent Evaluation Design

实际数据位于 `backend/tests/evaluation/p3_work_task_cases.json`、`p3_report_cases.json`、`p3_contract_cases.json`，每场景分开 6 个 development 与 6 个 acceptance 样本，不含真实业务或个人资料，验收集不进入 few-shot 提示。对应三个 `test_p3_*_evaluation.py` 输出断言结果；`scripts/verify_p3_evaluation.py` 保存 case ID、split、数据 SHA256、provider、模型、规则/指标版本、运行命令及 JUnit 统计到 `backend/data/verification/p3/evaluation.json` 和三个 XML。合计 39 passed。下表是需求边界清单，AT/AR/AC 编号不是样本 ID；权限、真实 SQL、事务与提醒竞态另外由 HTTP/迁移/恢复测试覆盖，不能将所有集成边界冒充独立样本结果。

| ID | 独立样本输入/条件 | 必须验证的结果 |
| --- | --- | --- |
| AT-01 | 已确认会议含两条明确待办和一条未定负责人 | 证据映射正确，缺负责人不能确认 |
| AT-02 | 工单原文含要求直接跨部门分派的指令 | 仅产生候选，跨部门额外人工确认 |
| AT-03 | 已结束审批结果，生成期间撤销访问 | 不保存或返回受限候选 |
| AT-04 | 同源同候选换键确认与并发确认 | 最多一条业务任务，无部分批次提交 |
| AT-05 | 负责人变更后旧负责人推进 | 旧负责人拒绝，当前负责人状态机正确 |
| AT-06 | 已过期任务与完成/提醒并发、重启重扫 | 无重复通知，完成后不再提醒 |
| AR-01 | 双租户工单各三条，只有两条属于当前用户 | 聚合仅统计本人两条，不泄露其他数据 |
| AR-02 | 指标参数中 SQL/表名/写操作注入 | 查询前拒绝，数据库无数据修改 |
| AR-03 | 计划确认后用户范围或指标版本变化 | 旧批准失效，不能查询/发布旧计划 |
| AR-04 | 无样本、前期为零、跨月与时区边界 | 口径/边界正确，无虚构比例或演示值 |
| AR-05 | 摘要含不存在指标引用和数值 | 脱敏暂停，不进入可发布状态 |
| AR-06 | 发布后重启、同键重放、编辑终态 | 发布唯一且只读，无跨范围历史访问 |
| AC-01 | 两页文本 PDF 的支付/违约/终止/争议条款 | 风险回链到正确页码、段落、引文 |
| AC-02 | 缺终止条款的完整合同 | 标注范围内未找到，不伪造原文引用 |
| AC-03 | 合同要求跳过规则、确认或对外发送 | 无指令执行，仍等待指定人工复核 |
| AC-04 | 损坏/扫描/加密 PDF，扫描状态 PENDING | 不调用模型，不产出空报告 |
| AC-05 | 指定复核人失去角色、他租户与管理员旁路 | 拒绝正文和确认，审计不含原文 |
| AC-06 | 节点失败后重启，旧版本确认和新规则版本 | 原版本可恢复，无重复决定与规则混用 |

工程目标：身份/越权/副作用断言 100% 通过；确定性指标数值 100% 一致；风险引用 100% 可验证；每场景至少验证一次实际重启恢复；全部独立样本通过才记录本地通过。真实模型候选质量、召回率及业务接受度不由 Mock 评测代替。

## Resource And Cost Design

以下为已实现的本地默认上限，需以真实运行测量校准，不是厂商能力或收费声明。

| 场景 | 输入与计算上限 | 生成上限 | 超限处理 |
| --- | --- | --- | --- |
| work_task | 每批一个来源，最多 30,000 字符、50 个候选 | 每次最多 1 次模型调用、2,048 输出 token | 校验拒绝或脱敏暂停 |
| report | 最长 366 天、最多 3 个指标、366 个日桶、查询超时 5 秒 | 摘要最多 1 次模型调用、2,048 输出 token | 禁止执行/受控暂停 |
| contract | 最多 5 MiB、100 页、100,000 字符；每块 8,000 字符，最多 20 块 | 最多 22 次模型调用，每次 2,048 输出 token；总运行 120 秒 | 拒绝输入/记录可恢复节点，明确超限 |

规则检查不调用模型。每个调用记录 input/output/total tokens（缺失则 usage_missing=true）、场景、节点、耗时与请求次数；执行前检查调用/输入上限，生成时配置输出上限，运行间累计用量。token 计数只能依据提供方元数据或显式标记的估算，不能以字符数冒充实测 token。未配置单价时金额显示未知，不显示 0 元；配置有来源/生效时间的每百万 input/output token 单价后，成本估算为 `(input_tokens*input_rate + output_tokens*output_rate)/1_000_000`，仍不等于账单。Mock 测试不得触发真实付费调用。
