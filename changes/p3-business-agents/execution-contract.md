## Scope Fence

内部任务和通知、内置指标聚合、平台报表发布、私有合同辅助报告及 DeepAgents 长文档分析接入。禁止范围扩大到外部 OA/BI/任务写入、真实发送、自动跨部门分派、任意 SQL、OCR/扫描件、DOCX、合同签署/自动修改、真实法规保证、付费调用。演示规则和 approver/admin 指定复核人映射须在 UI 与验收材料中明确；企业真实法务角色及规则另做验收。

## Build Rules

- 复用现有栈和身份刷新、业务 ACL、幂等、审计、策略/降级、模型轨迹设施；手工编辑使用 apply_patch。
- 增量迁移 0019-0022；0022 增加内部提醒的持久公平轮转。无有效提交基线，保留所有已有未跟踪文件，不假造提交范围。
- 顺序执行 B1-B6，每批测试和审查通过后再开始依赖批次。当前不存在有效 ssf 执行计划/凭据。
- 数据测试必须显式使用一致的 oa_agent_test 连接；不得截断 oa_agent。共用测试库的预览须先停止再做 reset 测试，完成后恢复。
- 图检查点与业务提交非原子；业务命令账本为决定权威，恢复和重复请求不可重复创建任务或决定。
- 当前技能/命令包缺 ssf 和脚本，不写虚假的 DP 状态、execution receipt、Git SHA 或归档记录。用户在说明本地替代方式及 DeepAgents 修订后回复“好，开始开发吧”，据此继续本地测试、审查及记录。
- 分支 codex/p3-business-agents，无提交基线。任务与报表模块可独立准备实现；依赖验收顺序保持 B1/B2 -> B3/B4 -> B5 -> B6，测试库重置串行。按 build-executor 授权委派实现和审查，模型配置工具缺失，保留实际继承模型，不编造解析结果。
