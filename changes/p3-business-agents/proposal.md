# P3 业务智能体开发提案

日期：2026-10-14。状态：B1-B6 本地工程完成，Mock 工程验收 Pass；实际证据见 reviews/verification.md，人工及生产验收待完成。

## Why

P2 已提供会议纪要、文档和邮件草稿，但会议待办仍是候选信息，现有任务中心主要展示智能体流程，不支持独立业务任务的负责人、截止时间、进度和归档。正式 PRD 的 F-060 至 F-065、AC-18 至 AC-21 要求进一步提供任务管理、权限内报表分析及可定位证据的合同审查。三者应复用现有身份刷新、人工确认、审计、幂等、灰度和恢复设施，避免新增业务绕过平台已有约束。

## What Changes

1. 任务管理：从有权限的已确认会议、内置工单、已结束审批结果提取候选，人工补齐并确认后创建平台业务任务；支持进度、完成、取消、归档、内部逾期提醒和升级待办。
2. 报表分析：登记内置工单、审批和业务任务三个指标集，生成可检查的查询计划，批准后执行参数化只读查询，产出指标、图表及异常候选，经人工确认后在平台内发布。
3. 合同审查：粘贴文本或上传 TXT/可提取文字的 PDF，保存版本和证据定位；通过条款提取、规则检查、风险分析、建议汇总四个 LangGraph 节点生成报告，经指定复核人确认后保存平台审查结论。
4. 三个场景独立开关、运行上限、评测、权限过滤、审计和重启恢复；任务中心可返回对应业务工作台。

## Scope

### In Scope

- 顺序实现任务管理、报表分析、合同审查及联合回归，覆盖三个领域的本地工程闭环。
- 新增 `work_task`、`report`、`contract` 场景及专用路由；保留 `/api/tasks` 的流程投影契约。
- 平台内任务及报表为本阶段的业务权威，不将内部结果标记为已同步外部 OA。
- 首批合同规则为版本化的演示规则；真实组织规则通过后续业务评审配置。
- 独立合成评测样本与失败/权限/恢复测试，实测结果与预设目标分开记录。

### Out of Scope

- 外部 OA/BI/任务系统同步、真实通知发送、自动跨部门分派。
- 邮件发送、公文发布、合同签署、代替法务判断和未经复核修改原合同。
- OCR、扫描 PDF、DOCX 导入、任意 SQL、模型生成 SQL 执行、外部数据库连接管理。
- 新模型部署、真实付费调用、全局组织目录及新企业 SSO。DeepAgents 纳入合同长文档分析的验证与受限接入。
- 自动归档原有 P1/P2 变更、清空开发数据库、覆盖用户已有文件。
