# M1 账号与组织底座规格

状态：用户已批准，B1–B5 已完成本地工程验证。范围对应正式 PRD V1.5 F-101 至 F-107；不包含 M2/M3 业务执行底座。

## ADDED Requirements

### Requirement: M1-01 持久化及非破坏迁移

系统 MUST 持久化账号、部门、岗位、归属、角色权限和可撤销会话；只扩张现有 schema。单组织使用稳定组织标识，与现有 tenant_id 兼容，不提供多租户产品能力。账号 ID 不复用 Mock ID，已有业务不自动改归属。

#### Scenario: 从已有工程结构升级

WHEN 隔离库已处于 0022 且有历史业务，THEN upgrade 保留业务内容和主键，新增结构可用，再次 upgrade 不重复创建；不执行清库、自动人员映射或启动建表。

### Requirement: M1-02 账号初始化与登录

系统 MUST 仅允许显式首管理员初始化和授权管理员建号；采用 Argon2id 哈希，无公共注册和默认口令。登录失败统一提示；同账号并发失败精确计数，达到 5 次锁定 15 分钟，成功登录重置未锁定失败计数；不存在的账号也受来源限流。

#### Scenario: 初始化及锁定

WHEN 已有有效管理员时再次初始化，THEN 拒绝新增管理员；WHEN 同账号达到第 5 次失败且服务重启，THEN 在锁定期内正确密码也不能登录，不泄露账号是否存在。

### Requirement: M1-03 可撤销令牌与刷新

系统 MUST 验证 JWT 签名、固定算法、issuer、audience、有效期、session_id 和账号会话版本；access 默认最多 2 小时，刷新会话绝对期限默认 7 天。refresh 为高熵不透明值，只存摘要，单次轮换；旧 refresh 重放撤销整个会话族。退出、改密、禁用使已有相关会话失效。

#### Scenario: 并发刷新及退出

WHEN 两个请求使用同一 refresh，THEN 行级并发保护只允许一次消费，另一请求按重放撤销会话族，原成功返回的新凭证也不可继续使用；WHEN 退出后重放 access 或 refresh，THEN 拒绝访问。

### Requirement: M1-04 权限即时复核

系统 MUST 从当前权威身份读取启用状态、部门、角色、资源动作和数据范围，不能从 Mock OA 或旧 JWT 角色补充 builtin 身份。请求、工具执行和后台恢复各自解析当前身份；高影响写入在提交前核对账号和授权版本，防止等待期间权限失效。

#### Scenario: 调岗与禁用

WHEN 已登录员工被禁用，THEN 后续受保护请求和刷新返回 401，后台任务不再以该人执行；WHEN 更换角色或部门，THEN 下一次业务访问使用新权限，不能继续读取旧部门材料。

### Requirement: M1-05 组织与默认拒绝授权

系统 MUST 管理部门树、岗位、成员归属和直属上级，拒绝环、跨组织引用及禁用目标。角色权限采用 resource/action/scope，范围至少 self/department；列表、详情、下载、导出及工具保持一致。管理员管理权不自动授予所有敏感业务读取权，最后一个可用管理员不得被禁用或移除管理角色。

通用 builtin 业务身份 MUST 支持自定义角色；写权限需包含相同资源且范围相同或更大的读权限。任务/报表读取关联来源时 MUST 再验证来源模块读权限，空来源缓存不豁免；M1 未接通的正式工单/审批来源返回 503。

#### Scenario: 管理与业务权限分离

WHEN 普通员工调用角色管理接口，THEN 403 且有拒绝记录；WHEN 管理员未获敏感业务读取授权，THEN 同样不能下载该业务附件；WHEN 部门 A 的员工访问部门 B 资源，THEN 列表不返回，直接访问按统一策略拒绝且不泄露材料。

### Requirement: M1-06 生命周期与审计

系统 MUST 支持账号禁用/启用、改密和角色部门调整；变更、会话撤销、授权版本更新及成功审计在同一事务完成。禁用后保留历史，显示待交接；M1 不伪造已完成待办转交。审计、日志和错误响应不得包含口令、哈希、access、refresh 或密钥。

#### Scenario: 禁用事务失败

WHEN 审计写入失败导致禁用事务回滚，THEN 不产生半禁用状态，返回可追踪错误；WHEN 禁用成功后再次启用，THEN 必须重新登录，旧会话不复活，未交接业务仍明确标识。

### Requirement: M1-07 前端会话与管理体验

系统 MUST 提供中文登录、退出、当前用户、部门/岗位/成员/角色管理和失效处理。access 仅放内存，refresh 使用 HttpOnly Cookie；页面刷新通过受限刷新接口恢复，同窗口刷新单飞。正式身份模式没有演示账号切换；菜单来自当前权限，后端独立授权。登录跳转仅接受站内路径。

#### Scenario: 页面刷新与越权页面

WHEN 登录后刷新页面，THEN 可安全恢复当前用户，不使用 localStorage 中 Mock 用户推断身份；WHEN 多请求同时遇到 access 过期，THEN 共用一次刷新，刷新失败统一退出；WHEN 非管理员直接打开组织管理地址，THEN 前后端均拒绝且不暴露人员清单。

### Requirement: M1-08 环境隔离与兼容验证

M1 的 builtin 管理入口仅开放组织管理。旧知识库管理、策略、运维和审计查询/导出尚有全局数据结构；在完成独立租户范围改造前返回 503，不允许通过新角色配置绕过。生命周期审计仍在数据库事务内写入，Mock 演示入口保持原契约。

系统 MUST 显式区分 mock/builtin 身份，未知配置失败关闭。生产仍拒绝 Mock 身份及 Mock OA；M1 未接通正式 OA 时不得移除整体生产门禁。测试仅使用经过校验的隔离数据库、Mock 模型和独立文件目录，旧业务 API 保持响应契约。

#### Scenario: 模式和验收边界

WHEN production 配置 builtin 身份但 OA_PROVIDER=mock，THEN 启动失败；WHEN development 显式 mock，THEN 旧演示流程可运行且没有宣称生产可用；WHEN 回归测试目标不是隔离库，THEN 在连接前拒绝执行，付费模型调用为零。
