# P1 正式化升级提案

## Why

当前系统已经能够演示请假预检与人工审批、FAQ 检索、工单创建、策略配置、知识文本导入和审计查询，但产品仍依赖 Mock OA 数据、单个浏览器保存的当前任务和开发期建表方式。多个页面展示了“可操作入口”，实际业务却缺少填单、逐级审批、驳回修改、人工接管、工单运营、知识版本治理和运行观测等闭环，因此尚不能作为正式 OA 产品独立使用，也不能安全地切换到真实 OA 环境。

本变更采用已确认的“双模式”产品形态：系统内置完整的 P1 请假、审批、FAQ 和工单能力，同时保留 `OAAdapter`，允许企业将权威数据与执行动作切换到现有 OA。第一阶段仅完成正式 PRD 的 P1 范围，不启动 P2/P3。

## Current Gap Audit

状态含义：

- `可用`：当前实现基本满足该条 P1 的核心验收点。
- `部分`：已有代码或页面，但正式流程、权限、数据或异常闭环不完整。
- `缺失`：没有用户可操作的完整实现。

### 工程化与上线门槛

| 领域 | 当前事实 | 正式化缺口 |
| --- | --- | --- |
| 数据库 | 启动时执行 `create_all`，虽安装 Alembic 但没有迁移版本 | 必须引入可回滚迁移和升级验证 |

| 发布运维 | 仅数据库 Compose，无完整生产部署和备份恢复 | 必须补环境配置、健康探针、日志、备份恢复和回滚手册验证 |

## What Changes

### 阶段 I：强化现有 MVP 功能

1. 建立正式数据迁移、隔离测试库、统一状态/错误/幂等契约和权限复核基础。
2. 修正当前请假审批：审批人只能处理当前节点，“编辑后批准”必须提交结构化修改，催办与升级针对当前节点，所有决定可恢复且可审计。
3. 修正现有 FAQ/工单：检索失败不生成答案，工单确认前字段可编辑，查询权限一致，人工路径保留完整交接上下文。
4. 修正现有管理和审计：策略校验与作用范围生效、知识状态过滤一致、审计查询字段和操作结果完整。

阶段 I 主要修复已经存在但行为不完整的能力。每个实施批次仍会在开工前报告目标、文件范围、数据影响和验收步骤。

### 阶段 II：补齐 P1 正式产品闭环

1. 服务端会话历史、当前任务中心和统一任务状态展示。
2. 内置请假申请/编辑页面、申请版本、附件元数据、重新预检和完整逐级审批实例。
3. 人工服务队列与客服工作台；工单合并、分派、处理回写和用户反馈。
4. 文件型知识入库、PDF/HTML/Markdown 解析、版本治理、预览和生失效管理。
5. 受控审计导出、运行观测、告警、恢复重试和一键降级演练。
6. 可配置真实 OA 适配器及其沙箱契约测试；未配置真实 OA 时使用内置权威存储。

阶段 II 中每一项均属于当前实现尚未包含的新功能。开始每一项前必须向用户报备，并等待明确确认，不以整份提案批准替代逐功能报备。

## Scope

### In Scope

- 正式 PRD V1.2 的 P1：F-001～F-044。
- 内置请假、审批、FAQ、工单及人工运营闭环。
- 外部 OA 的适配接口与可配置实现，不绑定某一家 OA 私有协议。
- 用户、审批人、客服、管理员、审计/运维五类工作入口和最小权限隔离。
- PostgreSQL 持久化、LangGraph 恢复、审计、运行观测、迁移和自动化验收。
- 开发环境继续提供 Mock 数据，但页面须明确标识，Mock 不作为生产实现。

### Out of Scope

- P2：会议纪要、文档生成、邮件处理（F-050～F-055）。
- P3：合同审查、报表分析、任务管理（F-060～F-065）。
- 自建企业 SSO、完整组织架构、人事主数据和通用 BPMN 流程引擎。
- 针对某个未提供接口文档的商业 OA 进行专有字段硬编码。
- 无人工确认的自动审批、自动外发或其他高影响动作。

## Delivery Decomposition

本变更拆成八个可独立验收的批次，防止一次性改动破坏现有演示数据：

1. **B1 正式化底座**：数据库迁移、测试隔离、统一契约、动态权限与安全基线。
2. **B2 现有请假流纠正**：严格当前审批节点、编辑决定、幂等、催办升级和异常恢复。
3. **B3 现有 FAQ/工单纠正**：字段可编辑确认、可靠人工交接、权限和恢复一致性。
4. **B4 会话与内置请假**：任务中心、历史会话、完整请假单、版本和附件元数据。
5. **B5 客服运营闭环**：人工队列、客服台、工单合并分派、用户反馈与复盘。
6. **B6 知识与策略治理**：文件解析、知识版本、权限/生效期、灰度和策略回滚。
7. **B7 审计、观测与降级**：受控导出、运行指标、告警、重试、一键回退演练。
8. **B8 真实 OA 适配与上线验证**：HTTP 适配器、沙箱契约、性能、安全、备份恢复。

B1～B3 属于现有功能正式化；B4～B8 含新增能力，必须逐批报备并确认后开工。每一批均先写失败测试，再实现最小代码，通过自动测试后提供手动验收步骤。

## Success Criteria

1. 员工可在页面创建、保存、修改、提交请假单；预检失败可按建议修改并重试。
2. 审批任务严格按当前节点流转，非当前审批人不能操作；驳回后保留版本和差异并重新预检。
3. 用户可查看自己的历史会话和任务，刷新、切换页面及服务重启后状态一致，已完成写操作不会重复执行。
4. FAQ 只基于有权限且有效的知识回答；未命中或故障时携带完整上下文进入人工队列。
5. 工单草稿可修改，可按规则创建/合并/分派；用户可反馈结果，负反馈进入复盘队列。
6. 管理员可治理知识版本和策略；审计/运维可查询完整轨迹、导出受控报告并查看运行指标。
7. 智能路径可按租户、部门或场景关闭；在途单据不丢失，内置路径或外部 OA 原路径可继续工作。
8. 所有写接口具备幂等保护，所有高影响动作具备人工决定记录，所有资源访问通过实时权限复核。
9. 数据库升级和回滚可重复执行；测试不触碰开发/生产数据库；关键后端、前端和端到端验收自动化通过。
10. P1 手动验收清单覆盖 F-001～F-044，并能由用户仅通过页面和明确的角色切换步骤完成验证。

## Impact

### Backend

- 扩展会话、请假申请/版本、审批实例/节点、人工队列、工单反馈、运行轨迹等领域模型。
- 新增列表、修改、重试、交接、反馈、导出和指标 API。
- 将 `RealOAAdapter` 从桩改为配置化集成实现，并保留内置适配器与 Mock 适配器。
- 引入 Alembic 版本迁移，停止依赖生产启动时自动建表。

### Frontend

- 从六个演示页面调整为按角色显示的任务中心、请假申请/审批、客服工作台、知识治理、策略、审计和运维入口。
- 所有长任务、错误、空状态和无权限状态提供明确下一步。
- 增加前端组件测试和关键流程 E2E 测试。

### Data And Operations

- 现有开发数据需经非破坏迁移保留；禁止用集成测试清空开发数据库。
- 审计导出和运行数据采用权限隔离、摘要脱敏和保留期策略。
- 上线前完成真实 OA 沙箱、安全、性能、降级、备份和恢复演练。

## Risks And Controls

| 风险 | 控制措施 |
| --- | --- |
| 大范围模型变更破坏现有测试数据 | 先建立 Alembic 基线和数据库备份，所有迁移采用前向兼容步骤 |
| 内置模式与外部 OA 模式行为分叉 | 以同一领域服务和 Adapter 契约驱动，两种模式运行同一套契约测试 |
| 审批纠正后旧任务无法继续 | 提供旧状态映射和只读兼容，迁移后对在途任务执行一致性检查 |
| 人工队列和观测带来敏感信息暴露 | 最小权限、字段脱敏、导出审计、保留期和资源级授权 |
| 范围过大导致长期不可验收 | 八个批次独立演示和验收，新增功能逐批报备，未批准批次不实现 |
