# P1 正式化升级执行契约

## Intent Lock

将当前演示型 MVP 升级为正式 P1 产品：内置完整的请假、逐级审批、FAQ、人工服务和工单闭环，同时保留可替换的真实 OA 适配能力；所有流程满足权限、幂等、恢复、审计、观测和降级要求。

批准来源：`proposal.md`、`specs/`、`design.md` 已由用户逐项确认；`tasks.md` 是本契约的执行清单。

## Approved Behavior

- F-001～F-004：服务端历史会话和任务、结构化状态、正式人工接管、暂停与安全恢复。
- F-010～F-013：五类意图、实时资源授权、可审计路由和动态工具白名单。
- F-020～F-026：完整请假表单与预检、严格逐级审批、编辑/驳回/版本差异、节点催办、故障暂停。
- F-030～F-035：权限证据回答、失败转人工、可编辑工单草稿、合并分派、多轮恢复和反馈复盘。
- F-040～F-044：版本化策略、知识来源/文件/版本治理、审计导出、运行观测和可控降级。
- P1-PLAT-001～009：内置/Mock/真实 OA 双模式、HTTP 适配、Alembic、测试隔离、统一幂等、正式认证契约、恢复、上线门槛和新增功能报备。

每项行为以 `specs/**/spec.md` 的 63 个 WHEN/THEN 场景为验收义务；不得以页面展示代替后端状态、权限和副作用验证。

## Scope Fence

不开发 P2/P3；不自建企业 SSO、完整组织人事主数据或通用 BPMN 引擎；不猜测商业 OA 私有接口；不允许自动审批或未经人工确认的高影响外部写入；不通过清库、重建或覆盖现有数据完成升级。

## Architecture Constraints

1. 业务规则只在 P1 领域服务实现，builtin/mock/real Provider 共用契约。
2. 关系表是业务权威；LangGraph 仅负责编排与恢复，写入前重新读取权威状态。
3. 请假采用申请版本、审批实例、有序节点和不可覆盖决定；每个实例最多一个活动节点。
4. 后端实施认证、资源授权、调用时复核和动态工具允许集；前端菜单不构成授权。
5. 所有副作用使用 `CommandEnvelope` 和幂等记录；不确定外部写入先对账再重试。
6. 人工接管、知识版本、策略版本、审计与运行 Span 均为正式持久化对象。
7. 数据结构使用 Alembic 扩张—迁移—切换—收缩；测试数据库必须通过三重安全校验。
8. 现有 API 在 B1～B3 保持兼容，旧入口转调新领域服务，不复制新旧业务逻辑。

## Build Rules

- 严格执行 `tasks.md` 的 30 项任务和每项 Red → Red Verify → Green → Green Verify → Refactor。
- 每批只修改其文件清单；新增必要文件前先更新任务文档并在报告中说明。
- 保护用户现有文件和数据，不运行 destructive Git/数据库命令。
- API/迁移测试只在隔离测试库执行；未建立安全闸门前仅运行安全的单元测试与前端构建。
- 每批更新手动验证文档，保存自动测试结果和已知限制。

## Test Obligations

- 每条 SHALL/MUST 已映射至 `tasks.md` 的 Requirement Coverage；无未映射需求。
- B1：迁移重复执行、开发库拒绝清理、幂等冲突、跨租户和生产 Mock 认证测试。
- B2：两级流转、越级/并发决定、编辑差异、驳回、节点催办和故障恢复测试。
- B3：FAQ 无依据不回答、交接幂等/脱敏、草稿修改、未确认不写工单和重启恢复测试。
- B4～B8：按规格覆盖员工、审批人、客服、管理员、审计/运维角色，并完成安全、性能、恢复和 E2E。

## Review Gates

1. 每批完成后执行规格符合性与代码质量复核；存在高风险缺陷不得进入下一批。
2. 数据迁移、授权、审批状态机、幂等或敏感数据处理变更必须有自动测试证据。
3. B4～B8 的用户批准只授权当前批次，不自动授权后续批次。
4. 全部批次结束后才能进入最终发布归档；P1 验收不以“构建成功”代替业务场景通过。

## Escalation And Rewind Rules

遇到以下情况停止实现并回到规划或请求用户决策：

- 需要新增 P2/P3、通用流程引擎、企业组织主数据等范围外能力。
- 真实 OA 接口与已定义 Provider 契约实质冲突，需改变权威边界。
- 现有数据无法非破坏迁移，必须删除、覆盖或不可逆转换。
- 新发现要求改变已批准的逐级审批、权限、幂等或人工确认原则。
- 一个批次连续三次因同一外部阻塞无法推进，且无安全替代路径。

普通实现细节、文件拆分或测试修正不触发重新规划，但必须保持规格行为不变。

## Approval Gate

用户已回复“开始吧”，批准执行。随后授权由实施者自行判断推进，功能完成后汇报；仅数据破坏、范围外能力或无法安全判断的产品选择需要再次确认。该最新授权替代 B4～B8 的逐批确认门，但不扩展 P1 范围。
