# 双模式平台与正式工程规格

## ADDED Requirements

### Requirement P1-PLAT-001：内置与外部 OA 双模式

系统 SHALL 通过统一领域接口支持 `builtin`、`mock` 和 `real` 三种提供方。业务服务和图节点不得直接读取 Mock 文件或依赖某个外部 OA 私有响应；提供方切换 MUST 由配置和能力探测控制。

#### Scenario: 内置模式完整运行

- **WHEN** 系统配置为 `builtin` 且未提供外部 OA 地址
- **THEN** 请假、审批和工单使用本系统持久化的权威实体完成 P1 闭环

#### Scenario: 真实 OA 能力不完整

- **WHEN** `real` 提供方能力探测发现缺少审批写入能力
- **THEN** 系统启动健康状态标记为降级，禁用对应智能写路径
- **AND** 不静默回退到 Mock 数据

### Requirement P1-PLAT-002：真实 OA HTTP 适配契约

真实 OA 适配器 MUST 支持配置化地址、认证、连接/读取超时、有限重试、幂等键、统一错误映射和请求关联编号。生产配置不得包含开发 Mock 凭证。

#### Scenario: 可重试读取失败

- **WHEN** 只读 OA 请求首次遇到瞬时网络错误
- **THEN** 适配器按策略有限重试并记录每次尝试
- **AND** 超过次数后返回可判定的依赖失败，不无限重试

#### Scenario: 写请求响应超时

- **WHEN** 写请求已发出但响应超时
- **THEN** 系统使用同一幂等键查询或重试，禁止以新键重复创建业务对象

### Requirement P1-PLAT-003：正式数据库迁移

所有数据库结构变更 MUST 通过有版本的 Alembic 迁移执行，并提供前向升级、兼容期和可验证的恢复方案。生产启动不得以 `create_all` 代替版本迁移。

#### Scenario: 从当前 MVP 数据升级

- **WHEN** 在包含现有会话、审计和知识数据的数据库执行正式化迁移
- **THEN** 迁移成功且现有记录仍可读取
- **AND** 新增必填字段通过默认值、回填或分阶段约束安全落地

#### Scenario: 重复检查迁移状态

- **WHEN** 已处于最新版本的数据库再次执行升级命令
- **THEN** 命令无破坏地结束且不重复回填业务数据

### Requirement P1-PLAT-004：测试数据隔离

自动化测试 MUST 使用明确标识的独立测试数据库或临时数据库。任何清表、回滚或夹具重置操作 SHALL 在执行前验证目标数据库为测试环境。

#### Scenario: 错误指向开发数据库

- **WHEN** 集成测试配置指向未标记为测试库的开发数据库
- **THEN** 测试会话在执行清表前立即失败
- **AND** 开发数据不被修改

### Requirement P1-PLAT-005：统一 API 写入契约

所有业务写接口 MUST 接受或生成幂等键，并返回 `request_id`、`trace_id`、业务状态和结构化错误码。相同主体、资源和幂等键的重复请求 SHALL 返回一致结果；载荷冲突 SHALL 明确拒绝。

#### Scenario: 相同键不同载荷

- **WHEN** 客户端使用已有幂等键提交不同业务载荷
- **THEN** 系统返回幂等冲突且不覆盖首次结果

### Requirement P1-PLAT-006：正式认证适配与最小权限

系统 SHALL 保留开发 Mock 认证并明确限制在非生产环境，同时提供正式认证适配契约以接收企业 SSO/JWT 解析后的用户、租户、角色和数据范围。生产环境检测到 Mock 认证 MUST 拒绝启动或标记为不健康。

#### Scenario: 生产环境使用 Mock 认证

- **WHEN** 环境标记为 production 且认证提供方仍为 mock
- **THEN** 服务拒绝进入可接收业务流量的健康状态

### Requirement P1-PLAT-007：可恢复与不重复副作用

系统 MUST 将任务状态、Checkpoint、幂等记录和权威业务状态关联。服务异常退出后 SHALL 从最后安全点恢复，并在调用写工具前对账已有结果。

#### Scenario: 审批写入后进程崩溃

- **WHEN** 外部审批写入成功但本地在保存完成状态前崩溃
- **THEN** 恢复时系统使用幂等键对账已有审批实例
- **AND** 不创建第二个审批实例

### Requirement P1-PLAT-008：发布、安全与恢复验证

正式发布 MUST 提供环境配置校验、就绪/存活探针、结构化日志、数据备份与恢复步骤、回滚步骤，以及权限越界、提示注入、性能、依赖故障和恢复演练记录。

#### Scenario: 上线门槛检查

- **WHEN** 准备将版本标记为可上线
- **THEN** 系统验证迁移、契约测试、关键 E2E、安全测试、性能基线和恢复演练均有通过证据
- **AND** 任一强制项失败时不得标记为可上线

### Requirement P1-PLAT-009：新增功能开工报备

对提案阶段 II 的每个新增能力批次，实施前 MUST 向用户报告目标、范围、预期数据/API/UI 变化、风险和验收方式，并取得明确确认。已有功能缺陷修复仍 SHALL 在批次开始时报告影响范围。

#### Scenario: 准备开发新增任务中心

- **WHEN** 规划进入包含服务端任务中心的新批次
- **THEN** 在修改实现文件前提交该批次报备并等待用户确认

#### Scenario: 未获确认

- **WHEN** 新增功能批次尚未收到用户明确确认
- **THEN** 可继续完善规格、测试计划或调查证据，但不得开始实现该新增能力
