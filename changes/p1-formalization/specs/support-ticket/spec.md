# FAQ、人工服务与工单规格

## MODIFIED Requirements

### Requirement F-030：基于权限证据回答

FAQ 回答 MUST 仅使用当前用户有权访问且处于生效期内的知识版本。每个回答 SHALL 展示文档标题、版本和可定位到页码、章节或段落的来源位置。

#### Scenario: 有权限知识命中

- **WHEN** 用户问题命中一份当前有效且用户有权限的文档
- **THEN** 回答仅依据命中片段生成，并展示可打开的来源定位

#### Scenario: 多权限文档混合命中

- **WHEN** 检索候选同时包含有权限和无权限文档
- **THEN** 无权限文档在送入模型前被过滤
- **AND** 回答、来源和日志摘要均不泄露其内容

### Requirement F-031：不确定和故障转人工

置信度不足、无检索结果、知识已过期或检索依赖失败时，系统 MUST 停止生成事实性答案，并创建携带上下文的人工服务项。

#### Scenario: 检索无结果

- **WHEN** 权限过滤后没有达到阈值的知识片段
- **THEN** 系统明确说明需要人工处理并创建人工服务项
- **AND** 不输出无来源的制度答案

#### Scenario: 向量服务故障

- **WHEN** 检索或嵌入服务失败
- **THEN** 系统记录错误和 trace_id 后转人工
- **AND** 用户输入与已有上下文保留在交接包中

### Requirement F-032：可编辑工单草稿

系统 SHALL 抽取工单类别、优先级、影响范围、问题摘要和必要上下文，并在创建前展示结构化草稿。用户 MUST 能修改允许编辑的字段，确认前不得创建正式工单。

#### Scenario: 用户修改抽取结果

- **WHEN** 系统将问题误判为低优先级，用户在草稿中改为高优先级并确认
- **THEN** 系统校验修改值并以确认后的字段创建或合并工单
- **AND** 审计记录机器值和用户确认值的摘要差异

### Requirement F-033：工单创建、查询、合并与分派

系统 MUST 支持工单创建、本人或授权范围查询、重复候选合并和按版本化规则分派。自动合并前 SHALL 向用户或客服展示候选依据；分派失败时 MUST 进入人工队列且不丢失上下文。

#### Scenario: 发现重复工单

- **WHEN** 新草稿与一个未关闭工单满足重复规则
- **THEN** 系统展示合并候选和依据
- **AND** 经确认后将新上下文追加到既有工单，而不创建重复工单

#### Scenario: 自动分派成功

- **WHEN** 工单类别和影响范围匹配一个有效队列规则
- **THEN** 工单保存目标队列、责任人或待领取状态以及规则版本

#### Scenario: 越权查询工单

- **WHEN** 用户查询不属于本人且未在授权范围内的工单
- **THEN** 系统拒绝访问且不返回工单字段

### Requirement F-034：多轮补齐与 Checkpoint

当工单必要字段缺失时，系统 SHALL 逐轮询问缺失字段并保存 Checkpoint。刷新页面或服务重启后，系统 MUST 恢复已采集字段和当前问题。

#### Scenario: 重启后继续补充字段

- **WHEN** 用户已完成两轮字段补充后服务重启
- **THEN** 再次打开会话时恢复已采集字段并继续询问剩余字段
- **AND** 不重新创建已确认的工单

### Requirement F-035：用户反馈与复盘队列

工单解决后，用户 SHALL 能标记“已解决”或“仍需帮助”并可填写说明。负反馈 MUST 重新打开或创建后续处理项，并进入人工复盘队列和运营统计。

#### Scenario: 用户选择仍需帮助

- **WHEN** 工单处于已解决状态且用户提交“仍需帮助”
- **THEN** 系统保存反馈、重新进入处理流程并创建复盘项
- **AND** 客服可查看原处理记录和反馈说明

#### Scenario: 重复反馈

- **WHEN** 用户以同一幂等键重复提交反馈
- **THEN** 系统只保留一次状态变更和一次复盘项
